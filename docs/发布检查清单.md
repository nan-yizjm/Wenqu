# 发布检查清单

当前版本 **0.2.3**，产品名 Wenqu。仓库名称保持 `obsidian-rag`，用户数据目录 `%LOCALAPPDATA%\ObsidianRAG`、安装 AppId 和主题存储键保持兼容。

## 版本与资源

升版同步核对：`src/product/__init__.py`、`src/product/resources.py`、`product.spec`、`installer/Wenqu.iss`、`web/package.json` 与锁文件、构建与安装验收脚本、当前用户指南、README、新版发布说明。旧发布说明不改版本。

## 验证顺序

1. CPU Python 全量测试、前端测试、生产构建、CSS token 检查、`pip check`、Python OSV 与 npm 审计。
2. 运行 `scripts/build_product.ps1`，任何外部命令失败立即停止。输出便携包和正式安装包；`-SkipInstaller` 仅用于便携构建。
3. 核对包内前端、当前用户指南、发布说明和许可证的 SHA-256 与源码产物一致；自验安装包 `.sha256`。
4. 运行 `scripts/test_installer.ps1`。它从同一便携包编译测试专用 AppId，使用临时目录验证静默安装、覆盖升级、旧入口清理和卸载保留，不覆盖正式卸载注册项。
5. 使用独立临时产品数据，运行交付版及 `node scripts/ui_acceptance.cjs <端口>`；补验导入、搜索、引用定位、收藏/导出、备份/恢复和重启。
6. 准确记录真实模型与测试替身的范围。更新当前发布说明、收尾报告与截图。
7. 推送源码并核对 CI，发布匹配提交的 GitHub Release，上传安装包、SHA-256 和验收说明。重新下载核对附件哈希后，才清理旧包与缓存。

## 安装与数据边界

相同正式 AppId 升级会沿用已登记的安装目录。旧品牌用户可能仍在旧目录内运行 Wenqu，这是兼容升级，不表示创建了空数据目录。安装程序只移除本次 `{app}` 内的旧品牌 EXE，不递归删除固定路径，也不删除个人数据。

测试专用 AppId 验证安装行为和数据保留；正式 AppId 的旧安装注册路径兼容在隔离注册环境中补验并记录。不要用临时 `/DIR` 对用户当前安装的正式 AppId 做实验。

打包前停止本次要覆盖的交付版进程。保留上一版已校验的 GitHub 归档；构建成功前不要删除最后一份可恢复交付物。
