# Obsidian RAG 0.2.1

在 0.2.0 首版可安装试用的基础上，补齐了 Notebook 资料类型、混合检索与暗色主题，并第一次把检索质量变成可复现的数字。

> **如果你试用过 0.2.0，请重新安装这一版。** 0.2.0 的安装包构建于 2026-09-15 02:14，其后有 16 个提交没有进包；其中包含本版的主要功能。

## 相对 0.2.0 新增

- **Jupyter Notebook（`.ipynb`）作为第三类资料**：只收录单元格源码和纯文本输出，图片等富媒体输出不参与检索，处理结果会注明丢弃了多少处；
- **混合检索**：BM25 与 E5 向量各自召回后经 RRF 融合，可在设置页开启。**默认仍是关键词检索**——原因见下方"检索质量的实测结论"；
- **暗色主题**；
- 来源面板：PDF 按页连续滚动、命中页自动定位并高亮命中文字；每条来源显示"为什么命中"以及相对相关度；
- **收藏的标签与筛选**：给收藏打标签，按资料库/标签/反馈类型/时间等维度筛选，并把一批收藏导出成一个 Markdown 专题文件；
- 问答答案按 Markdown 渲染；
- 加载、空态与错误态的整理；设置页保存不再被误判为非法。

## 相对 0.2.0 修复

- 后台向量索引构建中途资料发生变化时，不再被记成失败（那是"改做当前版本"，不是出错）；
- 切片上限收紧到 800 字符，避免片段超过 E5 的 512 token 上限而被静默截断；
- **查询里的问句模板不再吃掉主题词**：原先"有哪些风险"被整串删除，把"风险"一起删掉了，导致这类问题的检索几乎失去区分度。现在保留主题词，实测把 `retrieval-005` 的期望文档从第 4 名提到第 2 名，其余题目零变化；
- **超长片段不再无声无息**：索引建立时如果存在超过模型长度上限的片段，设置页和后台任务都会说明有多少个，而不是让语义检索悄悄只看前半段。

## 检索质量的实测结论（本版首次可复现）

本版新增了产品侧检索评测入口 `src/evaluate_product_retrieval.py`，跑产品自己的检索路径，同时给出两套判定口径：

- **严格**：只认预期的那份笔记排第几；
- **宽松**：任何完整覆盖期望关键词的文档都算对（Notebook、PDF、总览页都算）。

在 101 篇真实资料（56 Markdown + 44 Notebook + 1 PDF）上，dev 26 题的 Source Recall@1：

| 语料 | 检索方式 | 严格口径 | 宽松口径 |
|---|---|---:|---:|
| 101 篇 | 关键词 | 57.7% | 80.8% |
| 101 篇 | 混合 | 61.5% | 73.1% |
| 仅 56 篇 Markdown | 关键词 | 69.2% | 84.6% |
| 仅 56 篇 Markdown | 混合 | **84.6%** | 80.8% |

**混合检索没有设为默认，是因为上面这张表会随判定口径翻转**：严格口径下混合检索两种语料都赢，宽松口径下关键词检索两种语料都赢。在没有确定"什么算答对"之前，本版保持 0.2.0 的默认值不动——这是实测结论，不是没做完。

同口径实测被否决、因而**留在默认值上**的改动：重排（会把正确文档挤出前 5）、`rrf_k` 下调（R@5 与 MRR 双降）、Multi-Query（0 改善 4 退化）。完整数据与负结果记录见 `docs/产品检索评测-2026-09-16.md`。

## 已知限制

- **产品默认仍以关键词检索为主**；要用混合检索需先在设置页准备检索模型（读本机缓存或下载），模型未就绪时会自动退回关键词检索并在界面说明，不会假装已开启；
- **证据窗口按片段计，不按文档计**：一轮问答会放入 8 个片段，一份片段多、段落长的笔记可能独占多个名额，因此引用列表覆盖的文档数可能少于 8 篇；
- **`retrieval-019`（模型路由与级联）是已知的检索缺陷**：关键词检索下能排第 1，混合检索下掉到第 3。已定位到 RRF 只使用名次、不使用分数这一机制，修它需要改融合算法而非调参，本版未做；
- 扫描版 PDF 没有 OCR，复杂表格和图表不能可靠重建；
- 追问只覆盖常见代词和省略问法；
- 无账号、云同步、联网搜索、自动更新或遥测；
- 回答显示的有效引用只表示标签能对应到来源，不保证结论必然正确。

## 试用状态

开发机上的合成资料、真实浏览器、本机 Ollama、发布包与安装/卸载流程均已验收。0.2.1 安装包在临时目录完成了一次完整验收：静默安装、随包文档与示例的**文件名精确比对**、示例导入 → 建索引 → 搜索命中 → 重复导入幂等、覆盖升级后会话与示例数据保留、卸载后用户数据保留，以及打包资源落盘检查。

这次验收也修掉了**验收脚本自身**的两个缺陷（都不是产品问题）：① 脚本把 `application/json` 响应体当 ISO-8859-1 解码，中文文件名必然比对失败；② 在同一个数据目录上第二次调用时，仍断言"首次导入不应是重复导入"。两条断言此前从未真正执行过。详见 [Windows 安装交付学习记录](docs/学习记录/32-安装交付升级与恢复.md)。

至少两位朋友在各自电脑上的独立试用仍为**待试用**，不计为已完成。
