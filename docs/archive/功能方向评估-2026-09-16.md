## 一、Studio 式产出 + Deep Research + 代码执行

这一条要拆开看，五个子项难度和性价比完全不同：

| 子项 | 实现难度 | 谁已做 | 值不值得做 | 我的判断 |
|---|---|---|---|---|
| **学习指南 / FAQ / 简报** | 低 | NotebookLM、Notex | 做，但**不加分** | 就是 LLM 结构化输出（JSON/markdown 模板），你已有 DeepSeek，一天能出原型。但它是"功能"，不是"差异" |
| **思维导图** | 低 | NotebookLM、Obsidian 的 markmap 插件、Notex | 做 | 让 LLM 输出 Mermaid `mindmap` 或 markmap 格式，前端渲染即可。**注意：Obsidian 已有 markmap 插件和 Canvas**，你的差异只能是"直接从检索结果生成" |
| **闪卡 / 测验** | 低 | **Obsidian 插件已饱和**（LearnKit / RecallFlow AI / Flashcard Generator，全免费 + FSRS） | **做了也不加分** | 这一项我建议**别当卖点**。免费插件已经做得比你细（FSRS-6 排程、分组、移动端复习）。你要做也只能做"从检索结果一键出卡"，难度低但没壁垒 |
| **PPTX** | 中 | Notex（用"宝玉式 prompt"生成可编辑 PPT）、各家在线工具 | **伪需求** | 对个人笔记用户，PPT 基本用不上——真用的人（学生汇报、讲师备课）不在你的用户画像里。**建议缓做** |
| **Deep Research** | 中高 | NotebookLM | **最值得做的一项** | 但**必须限定在"你的库里"**：多跳检索 → 综合成一篇带双链的研究笔记。全网深研你打不过 Perplexity，库内多跳才是你的地盘 |
| **代码执行** | **高（风险）** | NotebookLM | **建议不碰** | 沙盒隔离是硬需求，Windows 桌面产品做任意代码执行是真安全问题。若真要做，退化成"受限数据分析"（对 CSV/表格做统计），优先级最低 |

**记忆要点**
- **Deep Research（库内版）是这一组里唯一值得投入的。**
- 闪卡/测验做了也不加分，因为免费插件已经饱和。
- PPTX 是伪需求，代码执行是安全债。

## 二、记忆系统

**先把概念掰清楚**：你的"知识"已经在 Obsidian 里了。记忆系统要解决的不是"记住知识"，是"**记住你**"——你的偏好、你的项目、你上次问过什么。

| 层次 | 内容 | 难度 | 值不值得 |
|---|---|---|---|
| 会话记忆 | 上次问了什么、追问上下文 | 低 | ✅ 做 |
| 偏好记忆 | 输出语言 / 详略 / 格式偏好 | 低 | ✅ 做 |
| 项目记忆 | 当前在做什么主题、关注哪批笔记 | 中 | ◐ 可做 |
| **自动事实抽取**（Mem0 式：从对话里抽实体、建关系、处理冲突、时序推理） | 很重 | **高** | ❌ 个人本地产品**不值得** |

**三条硬约束（隐私产品的底线）**
1. 记忆数据必须落 `%LOCALAPPDATA%\ObsidianRAG`，和现有数据一致
2. **必须能查看、能删除、能一键清空**——做不到这一点，你就成了自己批判的那类产品
3. 默认**关**，或首次使用时明确询问

**判断**：值得做，但排在后面，且只做前两层。**别上时序知识图谱**——那是给 Agent 开发商用的（Zep/Mem0/Letta 的战场），不是你一个个人知识助手该背的包袱。
*（置信：已核｜Zep/Mem0/Letta 定位为"AI 记忆层"，服务对象是 AI 开发者；ima 的四层记忆是消费级参照）*

## 三、MCP / API 上网搜索补充

**这是我的第一优先级建议，但它有个必须先解决的矛盾。**

**为什么优先级最高**
- NotebookLM 的**会话内不联网**是它写在明面上的短板（多源一致）
- MCP 已是 2026 的集成标准——连 NotebookLM 都有第三方 MCP Server 了
- 技术上不难：MCP 客户端接入是标准协议，搜索 API（Tavily / Brave / SearXNG）都成熟

**为什么不能直接做**
- 你的产品卖点是"**全本地、数据不出机器**"。一旦联网，这个承诺就被打破了。

**必须的设计约束（比技术实现更重要）**

| 约束 | 做法 |
|---|---|
| 显式开关 | 联网**默认关**，用户主动打开才生效 |
| 证据分层 | 返回结果必须区分"来自你的笔记" vs "来自网络"，**引用样式要不同** |
| 可溯源 | 网上补充的每一句都要给出来源链接，不能和库内内容混着说 |
| 失败可降级 | 断网 / API 失败时，静默退回纯库内检索，不能报错 |

**这一条最大的价值不是"能联网"，是"分层标注"**——它正好能复用你已有的证据层设计。云端产品做不了这个（它们不区分），本地产品大多没做到。

## 六、这个空位是真的：产出回链

上面所有"别人已做"的东西，都缺同一件事——

> **没有一个方案能让产出物落回你的 Obsidian 库，并且每个产出都能回链到原始笔记。**

对比一下就清楚了：

| 方案 | 能生成 | 产出落在哪 | 能回链源笔记 | 检索质量可验证 |
|---|---|---|---|---|
| NotebookLM | ✅ 全套 | **Google 的笔记本里**（多源指出：**没有一键导出**） | ✗ | ✗ |
| Open Notebook / Notex / Gloss | ✅ 部分 | 独立应用的数据库 | ✗ | ✗ |
| Obsidian 插件（LearnKit / Copilot） | ◐ 只有闪卡类 | vault 里 | ◐ | ✗ |
| **obsidian-rag 可以做成** | ✅ | **vault 里（.md / markmap / Canvas）** | **✅ 每张卡、每个测验题回链到源片段** | **✅** |

**所以你的差异不在"会不会生成"，在"生成之后落在哪、能不能点回去"。**

具体就是：
- 生成一篇研究笔记 → 落成 vault 里的 `.md`，正文里带 `[[双链]]` 指回源笔记
- 生成一组闪卡 → 落成 markdown 卡片文件，每张卡带源笔记链接（不做排程，排程交给现成插件）
- 生成思维导图 → 落成 markmap/mermaid 代码块，进 vault 就能渲染
- 生成学习指南 → 每条要点带 `^block-id` 块引用，点回去就是原文

**这一条，上面所有竞品都做不到。**

## 七、风险（必须直视）

1. **重心偏移**：这四条会把产品从"检索问答工具"变成"内容生成工作台"。你的核心资产是**检索质量可验证**——生成做得花哨但检索没进步，就是舍本逐末。
2. **单人体量**：每加一个能力，维护成本线性增长。你现在是一个人，还有 0.2.1 安装包没重打。
3. **承诺冲突**：联网破"全本地"，代码执行担安全责任，云 TTS 破隐私。**每一条都要先想清楚代价**。
4. **反方（我自己的反例）**：如果你的目标是"**作品 / 求职**"而不是"**产品**"，那做这四条反而是加分的——它们能展示工程能力。**只是它们不构成产品护城河。** 这个取决于你要什么，我不替你定。

## 八、待你拍板

1. **这个项目是"产品"还是"作品"？** —— 这一个问题决定上面所有取舍。产品就按我对优先级的建议走；作品就按"展示工程能力"来选。
2. **联网补充的开关默认值**：默认关（守隐私）还是默认开（好用优先）？
3. **产出回链这个差异点，认不认？** 如果认，那"生成"这一块的验收标准应该是"产出能不能点回源笔记"，而不是"生成了多少种格式"。
4. **代码执行**：确认不做，还是要退化成受限数据分析？
