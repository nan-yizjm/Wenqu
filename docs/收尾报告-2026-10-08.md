# Wenqu 0.2.3 收尾报告

本次范围是安全修复、测试、文档、打包发布与冗余清理，不新增产品功能。仓库继续保持私有，用户数据目录与正式安装 AppId 保持兼容。

## 修复与证据

| 问题 | 处理与回归覆盖 |
| --- | --- |
| Ollama 地址前缀校验可被伪装域名和用户信息段绕过 | 按 URL 解析协议、主机、端口与路径，拒绝非法配置并返回 422；覆盖 `localhost.evil`、`127.0.0.1@evil`、无效端口、协议与空白字符 |
| 本机不同端口或伪造 Origin 可绕过来源检查 | Origin 与请求协议、主机和端口精确匹配，非法来源返回 403；无 Origin 的本机 API 调用仍兼容 |
| ZIP 恢复在 Windows 下可能越界或覆盖规范化后的同名文件 | 拒绝反斜杠、盘符、穿越、保留设备名、非法字符、符号链接、大小写重名；写入前再确认恢复目录边界 |
| 损坏清单或数据库产生 500 | 校验清单对象、版本、文件元数据、长度及 SHA-256；损坏 ZIP、清单与 SQLite 统一拒绝，测试确认原数据库与资料不变 |
| 自动渲染首先选择的 Edge 失败后不尝试 Chrome | 自动候选依次尝试，为后续浏览器保留超时预算；显式指定时保持该选择；失败记录原因，临时文件和进程清理后才降级到 HTML |
| 构建可能忽略外部命令的失败 | npm、pip、许可清单、PyInstaller、Inno Setup 的失败立即终止构建 |
| 临时安装验收可能触碰正式安装 | 验收重新编译专用 AppId，隔离安装目录与数据目录；升级仅删除本次 `{app}` 的旧入口，不递归删除固定旧品牌目录 |

| source-map-js | 1.2.2（锁文件） | 前端构建的间接依赖；产品发布的是编译后静态资源，不运行 Node source map 工具。已修补，避免构建侧风险。[公告](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) |
| pypdf | 6.19.0 | 产品上传 PDF 时调用 `PdfReader` 与文字提取；具体公告触发条件与 PDF 内容相关，不能把全部解析路径等同于已复现利用。已升级。[公告](https://github.com/advisories/GHSA-php9-fj8v-98fj) |
| python-multipart | 0.0.31 | FastAPI 的上传接口确实解析 multipart 请求，属于运行时调用路径，已升级。[公告](https://github.com/advisories/GHSA-5rvq-cxj2-64vf) |
| setuptools | 83.0.0（构建环境） | 用于依赖和打包构建；产品没有调用公告涉及的安装下载入口，仍固定修补版本。[公告](https://github.com/advisories/GHSA-h35f-9h28-mq5c) |

本机 CPU 环境 OSV 审计查询 62 个已安装包，已知公告命中为 0；`pip check` 通过，npm audit 命中为 0。审计不可用时脚本退出失败，避免把网络故障当作通过。这是检查时点的已知依赖公告结论，不是对所有代码的安全证明。

284 个原有已跟踪文件没有内容完全相同的副本。保留产品与实验源码、测试、题集、学习记录，历史规划移入 `docs/archive/` 并修复链接。训练权重、原始私人资料、工作记录与必要实验证据继续在本地保存，密钥和私人语料不上传。

本地删除在最终包验收、远端附件下载校验与 CPU 测试通过后执行。待核验清单包括旧 CUDA `.venv`、两套旧便携目录、已归档旧安装包、构建缓存与本次临时演示 / 浏览器产物。保留 `.venv-product`、前端依赖、最新便携目录和安装包；CUDA 重建方法见 [实验环境重建](实验环境重建.md)。实际删除清单与释放字节数在完成后写入本节。
