# Obsidian RAG 朋友试用与反馈

这份清单用来验证“一个不参与开发的人，能否独立完成安装到导出”。请不要先教每一步；只在试用者已经卡住时记录现象并提供必要帮助。

## 1. 隐私要求

- 使用代号，不记录姓名、邮箱或其他身份信息。
- 首轮使用随安装包提供的合成示例资料，不要上传朋友的私密笔记到 GitHub Issue。
- 只提交脱敏诊断。截图前检查文件名、对话和路径。
- 不记录 API Key；如果选择 DeepSeek，由试用者自己输入。

## 2. 测试前记录

```text
试用 ID：
日期：
Windows 版本：
是否有独立 GPU：有 / 无 / 不知道
生成后端：Ollama / DeepSeek / 暂不配置
安装前是否有 Python：有 / 无 / 不知道
安装前是否有 Node.js：有 / 无 / 不知道
```

Python 和 Node.js 只用于确认产品是否真的独立，不要为了试用去安装它们。

## 3. 核心任务

| 步骤 | 用户任务 | 成功标准 | 记录 |
|---|---|---|---|
| 1 | 运行安装程序并打开工作台 | 不使用终端，浏览器显示首次向导 | 成功/卡住，耗时 |
| 2 | 在未配置生成模型时进入设置 | 页面可用，清楚显示缺少什么 | 是否看懂 |
| 3 | 准备检索模型 | 看到进度，最终显示 CPU 就绪；失败可重试 | 结果，耗时 |
| 4 | 导入“欢迎使用.md” | 文档由处理中变为可搜索 | 结果，耗时 |
| 5 | 搜索“PagedAttention”并打开来源 | 能看到命中原文和定位 | 来源是否对 |
| 6 | 配置 Ollama 或 DeepSeek | 页面显示后端可用，不编辑配置文件 | 卡住点 |
| 7 | 提问、停止或重试，再进行一次追问 | 有流式状态，刷新后会话仍在 | 结果，耗时 |
| 8 | 点击回答引用 | 右侧打开回答当时的原文快照 | 定位是否正确 |
| 9 | 收藏回答、修改标题/备注并导出 Markdown | 重启后收藏仍在，导出文件可在 Obsidian 阅读 | 是否愿意保留 |
| 10 | 在设置中下载备份和脱敏诊断 | 文件可下载，诊断中没有问题和文件名 | 结果 |

只有 1～9 全部完成，才计为“安装到导出的核心流程成功”。步骤 10 用于交付支持验证，不用来掩盖前面的卡点。

## 4. 如何记录一个问题

```text
问题 ID：
试用 ID：
出现在第几步：
用户当时想做什么：
实际看到什么：
用户最后如何继续：自己解决 / 需要提示 / 无法继续
可否稳定复现：
脱敏诊断或版本：
备注：
```

严重程度：

- **P0**：数据丢失、密钥/原文泄露、恢复不可用等高风险问题；
- **P1**：无法完成安装、导入、提问、查看引用或导出中任一核心任务；
- **P2**：有绕行方式，但指引不清、等待无反馈或操作容易错；
- **P3**：不影响主流程的视觉、文案或功能建议。

## 5. 下一版如何决定

1. 先修 P0，不等待收集更多功能建议。
2. P1 按“阻断的核心步骤 + 出现人数”排序。
3. P2 优先处理多人重复遇到或显著增加等待的问题。
4. OCR、多资料库、专题整理、Obsidian 集成等候选功能，只在核心阻碍稳定后，根据真实任务和多人需求决定。
5. 不用模型评测分数替代用户任务结果；两者回答的问题不同。

开始阶段 33 的最低数据是：你和至少两位朋友各完成一次记录。未获得这些记录前，任何“高频问题”或“下一版优先级”都只是假设。
