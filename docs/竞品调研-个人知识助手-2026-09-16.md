## 一、一页纸结论

**先说三句话，每句都是判断，不是罗列：**

1. **这不是一条赛道，是四条。** 笔记软件自带 AI、通用 AI 挂知识库、专门的"第二大脑"、开源自建 RAG——四类东西的用户不是同一批人，护城河也不在一个地方。混在一张表里比，结论必然是"各有千秋"，没法用。
   *（置信：已核｜多源一致：WTF Radar 2026、TBRC/GII 市场报告、国内横评均按此分法）*

2. **你的直接对手不是 NotebookLM，也不是 RAGFlow，而是跑在 Obsidian 里、免费、装个插件就能用的那几个。** Copilot（~7.7k★）、Smart Connections（~5.4k★）、Khoj（~36.9k★ 的插件端）。它们和你在同一个 vault 里，抢同一个"问笔记"的入口。
   *（置信：已核｜Obsidian 官方定位"不做 AI"，生态全让给插件，多源一致）*

3. **你唯一别人抄不走的资产，可能不是功能，是"能证明自己检索质量"。** 我查了 30+ 个产品与项目，**没有一个公开自己的检索评测集**。你有（`src/evaluate_product_retrieval.py`）。这件事的价值现在被严重低估。
   *（置信：估算｜基于"公开资料未见"推断，不排除有未公开的；反方见 §8）*

**你的位置（一句话）**：本地优先 + Obsidian 原生 + 引用可溯源 + Windows 一键装。**前三样别人也有，第四样才是你今天真正稀缺的能力。**

## 六、动态分析：别只看"是什么"

**① 时间维度**——现在才进晚不晚？
2024 是起跑年（NotebookLM 音频概览引爆），2025 是混战年，**2026 的关键词是两件事：Agent 化 + 本地优先**。Stanford HAI 2026 AI Index 把"agentic AI 部署的急剧加速"列为年度主线；CES 2026 上厂商集体打"Personal Knowledge Graph"和本地 NPU。结论：**赛道不新，但"本地 + 可验证"这个细分窗口还没被占死**——大厂都在抢云，小厂在抢通用。*（置信：单源偏多｜来自 Vellum/TokenRing 等二手分析，方向一致但需谨慎）*

**② 成本结构（钱怎么流）**——这是多数人漏掉的一层

| 形态 | 用户实际付出 | 谁承担模型成本 | 隐性成本 |
|---|---|---|---|
| 云 SaaS（Notion/NotebookLM/Mem） | 订阅 $10–20/月 | 厂商 | 数据出境、锁定、断网不可用 |
| 插件 + 云 API（Copilot 默认） | 免费 + 按量 API 费 | 用户 | 大库索引费不可控、笔记出本机 |
| 插件 + 本地模型（Smart Connections） | 免费 | 用户（电费 + 硬件） | 16GB 内存起、初次索引耗时 |
| 自建 RAG（AnythingLLM/Khoj） | 免费 + 硬件 | 用户 | 部署与维护、空载 ~2GB 内存 |
| **obsidian-rag（当前）** | 免费/一次性 + DeepSeek 按量 | 用户 | 密钥管理、模型就绪检测 |

> 本地推理约 $0.02/百万 token（电费）vs 云 API $0.50–15。**对"每天问几十次"的个人用户，本地/混合方案的成本优势是数量级的**，但代价是硬件和设置摩擦。*（置信：单源｜Dev.to/Cumulus 口径，量级参考）*

**③ 地域维度**——不能用一个"个人知识助手市场"概括
- **海外**：NotebookLM / Notion / Mem / Khoj / AnythingLLM 主场，数据出境合规敏感，隐私是购买理由。
- **国内**：**生态绑定才是护城河**。ima 绑微信（公众号一键入库），飞书绑飞书，语雀绑阿里。**没有一个"中立、本地、跨生态"的个人知识助手跑出来过。** 这是空位。
- **obsidian-rag 落点**：Windows 用户 + Obsidian 用户 + 中文语料。既不是国内大厂生态战，也不是海外隐私战，是**"中文 Obsidian 用户的本地检索"**这个窄缝。*（置信：已核｜国内横评多源一致指出生态绑定为核心）*

**④ 可行路径**——不把建议甩回给你
- **若你走"个人作品/口碑"路线** → 必须零配置：一键装、自动找 vault、默认能跑（哪怕先只有 BM25）。别让用户配 key 或装 Docker。
- **若你走"技术示范/求职作品"路线** → 把检索评测集做深、开源、写清楚方法，让它成为你的名片，产品反而是附属。
- **若你走"小规模付费"路线** → 先解决"跟免费插件比凭什么收钱"，答案只能是插件给不了的：Notebook 索引 + 大库性能 + 块级引用 + 可验证质量。

**⑤ 利益相关方**——同一事实，三种人看到三种东西

| 谁 | 关心的 | 你该给他看 |
|---|---|---|
| Obsidian 普通用户 | "装了会不会变慢/被盗" | 离线、不吃内存、卸载不删数据 |
| 技术评审 / 面试官 | "检索到底行不行" | 评测集 + 消融实验 + 基线对比 |
| 潜在付费者 | "比免费插件强在哪" | Notebook 支持 + 大库速度 + 引用精度 |

**⑥ 因果机制**——你为什么可能打不过免费插件
插件赢在**分发**（插件市场即渠道，零安装摩擦），输在**能力上限**（跑在 Obsidian 进程里，重模型/大批量索引受限）。所以你只有一条路：**做插件做不到的事，而不是把插件能做的事做得更好看。**

## 七、对 obsidian-rag 的差异化结论

**能守住的（别人短期内补不上）**

| 资产 | 为什么稀缺 | 证据 |
|---|---|---|
| **公开的检索评测集** | 30+ 产品/项目中未见第二个公开 | `src/evaluate_product_retrieval.py`；已产出 Source Recall@1/@5/@8 + MRR |
| **Notebook(.ipynb) 入库** | 主流方案普遍只吃 md/pdf | 你的语料 101 篇含 44 个 ipynb |
| **产品级离线 + 凭据托管** | 插件方案要用户自己管 key | 密钥进 Windows 凭据管理器，数据落 `%LOCALAPPDATA%` |
| **混合检索 + 完整块上下文** | 插件多为单路向量或云 RAG | BM25(k1=1.5,b=0.75) + E5 + RRF(60) → 完整块 |

**不该碰的（投入产出比低）**
- 多模态产出（音频/PPT）—— NotebookLM 已封死，重资产。
- Agent 自动整理全库 —— Claudian 已占位，且风险高（批量删改文件）。
- 团队协作/权限 —— 不是个人产品的战场，且重交付。
- 跨平台同步 —— Obsidian 自己做 Sync，你打不过。

**最大风险（必须直视）**
> 插件免费、在 vault 内、跨平台。**你的独立桌面 App 增加了安装摩擦，却可能只做到插件能做的事。** 如果评测集证明不了"检索质量显著更优"，那么这个产品的存在理由就不成立。

## 八、我自己推翻 / 存疑的两个判断

1. **"公开检索评测集是独有优势"——可能是幸存者偏差。** 我只搜了公开资料，大厂内部一定有评测集（NotebookLM 的锚定质量不可能没测过）。所以准确表述是"**在公开可查范围内，个人/小团队产品里，你是唯一把评测当卖点的**"。这不影响策略，但别在对外材料里说成"业界唯一"。
2. **"本地优先是趋势所以能赢"——不严谨。** 本地优先确实是 2026 主流卖点（多源一致），但主流卖点 ≠ 用户会为此换工具。Smart Connections 78.6 万下载证明用户愿意为"离线"买单，但它**免费**。**收费的本地优先，在这个生态里还没有验证过的成功案例。** 这是我目前最大的不确定。
