# 28：产品骨架与安装验证

日期：2026-09-15

## 1. 用户问题与阶段目标

旧项目能在开发机上运行，但朋友仍需要 Python、命令行、配置文件和已有索引。产品的第一道门槛不是回答质量，而是：**程序能否在尚未配置任何资料和模型时打开，并告诉用户下一步做什么。**

本阶段只建立产品底座，不假装资料管理和问答已经完成。验收链路是：

```text
安装程序 → 独立 EXE → 本地服务 → 浏览器网页 → 首次设置
                                     ↓
                         下载固定 E5 → CPU 加载 → 向量检查
```

## 2. 做了什么

### 2.1 独立产品入口

新增 `src.product_entry`，保留旧 `/v1` 实验服务，不让产品改造破坏历史 CLI。产品 API 使用 `/api/v1`：

- `GET /api/v1/health`：服务、版本、数据库版本和运行状态；
- `GET /api/v1/setup`：向导步骤和配置状态；
- `GET/PATCH /api/v1/settings`：普通设置；
- `PUT/DELETE /api/v1/credentials/deepseek`：远端密钥；
- `GET/POST /api/v1/setup/retrieval-model`：模型状态与准备任务；
- `GET /api/v1/system/diagnostics`：不含正文和密钥的运行信息；
- `POST /api/v1/system/shutdown`：让启动器正常退出。

产品服务即使没有资料、索引、Ollama 或 E5 也会启动。模型采用延迟导入，避免设置页被重量依赖阻塞。

### 2.2 数据和密钥分离

用户数据根目录为 `%LOCALAPPDATA%\ObsidianRAG`，包含：

```text
workspace.sqlite3
backups/  corpus/  exports/  indexes/
logs/     model-cache/  runtime/  snapshots/
```

SQLite 通过 `PRAGMA user_version` 管理迁移，迁移前复制数据库到 `backups/`。普通设置进入 SQLite；DeepSeek Key 经 `keyring` 写入 Windows 凭据管理器，不进入数据库、日志或前端回显。

### 2.3 首次设置和网页骨架

前端使用 React、TypeScript、Vite，构建结果由 FastAPI 同源提供。首次进入选择工作台名称和 Ollama/DeepSeek；进入后保留资料库、知识问答、收藏和设置四个产品区域。现阶段后三个业务区仍是明确的空状态，而不是无法操作的假按钮。

网页移除了在线 Google Fonts 依赖，离线安装时使用 Windows 自带中文字体。Host 和 Origin 只接受本机地址，避免浏览器中的外部网页借本地接口读取数据。

### 2.4 E5 首次准备

检索模型固定为 `intfloat/multilingual-e5-small` 的指定 revision，默认 CPU。用户点击后后台线程经历 `downloading/loading → verifying → ready/failed`。完整性检查不是“文件存在”判断，而是实际编码测试文本，并验证：

- 向量维度为 384；
- 数值有限；
- L2 范数约等于 1；
- 模型名、revision、device 和时间写入状态文件。

真实验证结果：打包后的 EXE 内加载成功，`dimension=384`、`device=cpu`。

### 2.5 Windows 启动与交付

启动器实现：

- 单实例文件锁；
- 从 8765 开始寻找本机空闲端口；
- 将真实端口写入 `runtime/instance.json`，再次启动时打开正确地址；
- 自动打开浏览器；
- 通过网页请求正常退出；
- 日志写入用户数据目录。

发布使用 Python 3.12 CPU 环境、PyInstaller `onedir` 和 Inno Setup 当前用户安装。发布包包含 Python 解释器、后端依赖和网页资源，不要求目标机安装 Python、Node.js 或 Docker。

## 3. 遇到的真实问题

### 3.1 SQLite `with connection` 不会关闭连接

最初测试结束时 Windows 报 `WinError 32`，临时数据库仍被占用。`sqlite3.Connection` 的上下文管理器只负责提交或回滚，不负责 `close()`。统一改为 `contextlib.closing()` 后，测试目录可以立即删除。

### 3.2 TypeScript 7 不认识 CSS 副作用导入

`import './styles.css'` 触发 TS2882。增加 `vite-env.d.ts` 引用 `vite/client` 后通过。这说明“浏览器能识别 CSS”与“类型检查器知道这种导入”是两层问题。

### 3.3 Windows PowerShell 5.1 错读 UTF-8 脚本

无 BOM 的脚本包含中文错误文本时，旧 PowerShell 按系统代码页解释，中文字节甚至破坏字符串引号。构建和烟雾测试脚本的控制文本改为 ASCII；中文学习说明保留在 Markdown。

### 3.4 `py -3.12` 不一定找到已安装的 3.12

本机 3.12 来自 Astral 运行时，在 `py -0p` 中可见，但 `py -3.12` 返回“不匹配”。构建脚本改为从 Launcher 清单解析实际 3.12 路径，再创建 `.venv-product`。安装来源不能被当作版本本身。

### 3.5 无控制台 EXE 与 Uvicorn 日志不兼容

首个打包程序进程一直存在，却没有监听端口。写入文件日志后定位到：窗口模式下 `sys.stderr is None`，Uvicorn 默认 formatter 调用 `isatty()` 抛错，并停在隐藏错误对话框。修复方式是产品自己写文件日志，Uvicorn 使用 `log_config=None`；冻结程序异常时记录后以非零状态退出。

### 3.6 安装路径过长

使用很长的随机临时目录测试时，PyTorch 附带的深层第三方许可证路径超过传统 Windows 路径限制，Inno Setup 回滚并返回 5。真实默认安装路径较短并可安装；测试路径改为接近默认路径长度。发布包仍有约 626 MB onedir、165 MB 压缩安装器，依赖和路径裁剪留到阶段 32，不能把“默认路径通过”误写成“任意长路径都支持”。

## 6. 你可以手动练习

1. 为什么数据库文件要放在安装目录之外？
2. 为什么“EXE 能启动设置页”和“E5 能在 EXE 内加载”必须分成两个测试？
3. 如果 8765 被占用，第二次双击程序应打开哪个端口？这个端口保存在哪里？
4. 为什么 DeepSeek Key 不能和 `provider=deepseek` 一起存进 SQLite？

参考答案：

1. 升级或卸载会替换安装目录；用户资料必须独立保留，也不能要求安装目录可写。
2. 前者只覆盖轻量 Web 依赖，后者才覆盖 PyTorch、Transformers、模型文件和 CPU 动态库；空网页通过不能证明检索可用。
3. 打开第一个实例实际选择的端口；记录在用户数据的 `runtime/instance.json`，不能写死 8765。
4. 普通配置可读、可备份；密钥需要系统级安全存储，并且诊断、数据库备份和前端状态都不应包含其明文。
