# 阶段 6：Token 感知切分实践

日期：2026-09-12。本轮从上一轮的“70 个超限片段”继续推进。原笔记、旧 documents.json、旧 chunks.json 和旧向量缓存均未覆盖。

## 要解决什么

旧切片上限为 1200 字符，但 E5 接受的模型 token 数不是字符数。中文、英文、符号、代码经过 tokenizer 后占用不同；还必须算上 `passage: `、标题路径与格式前缀，不能只数正文。

## 实现了什么

- 新增 `src/markdown_structure.py`：识别标题、段落、列表条目、表格和两种围栏代码；保留字符坐标。
- 新增 `src/token_chunking.py`：基于 E5 的真实 tokenizer 切分，每个完整 passage 最多 480 token。
- 使用现有 52 篇文档快照重新切分，输出独立的 `data/generated/token_v1/`。
- 片段增加原文字符起止位置、文档快照行号、文档内容指纹、token 数与续片标记。
- 新 ID 由来源路径、标题路径、片段内容的哈希及重复序号组成。插入无关章节不会仅因章节序号变化而重命名原片段。

入口函数：`TokenChunker.create_chunks` → `sections_with_offsets` → `split_section` → 必要时 `split_oversize`。

## 切分规则

先按章节分，再尝试将完整 Markdown 块装入预算。装不下就开始下一片；仅对本身就超限的块继续拆，优先换行和句末边界，最后才按字符边界切开。

相邻片段最多尝试重叠 32 token 的完整小块。这是上限，不保证每对片段都有恰好 32 token 的重叠；不会为了满足重叠量强行截取半段代码。

每个候选都重新计算带标题、前缀的完整 passage 长度，最终还会检查全部输出。token 数不满足约束时直接报错，不悄悄继续生成坏索引。

## 遇到的问题与处理

### 1. 原文位置不能依赖“解码后的文本”

若先切 token ID 再 decode，空格或文本形式可能改变，回到原笔记就难以精确定位。本版截取原始字符串，保存 `[source_start_char, source_end_char)`；可以检查它与 chunk.text 完全一致。

这些坐标针对输入的 documents.json 快照。你后来修改了 Vault 文件，旧行号不能直接当成新文件行号；需结合文档 SHA-256 判断版本。

### 2. 代码内部的 `#` 不是 Markdown 标题

识别反引号与波浪线围栏，关闭围栏必须与开启字符相同且长度足够。比开启围栏更短的一行不会意外结束代码块。该模块仍是轻量识别器，不是完整 CommonMark 解析器，复杂嵌套列表和缩进代码仍有边界。

### 3. 一个代码块本身就超过模型窗口

“完整保留代码块”与“绝不超过窗口”不能总是同时满足。这里优先保证长度并标记 continuation，后续上下文明确说明它是续片，不伪装成完整程序。

### 4. 同样数量的片段不意味着内容相同

输出目录携带 manifest：文档快照 SHA-256、模型 revision、格式模板、token 上限、重叠设置和诊断。向量缓存根据新 chunks 指纹独立生成；旧缓存继续保留。

## 实测结果

| 项目 | 旧切片 | 新切片 |
|---|---:|---:|
| 文档快照 | 同一份 52 篇 | 同一份 52 篇 |
| chunk 数量 | 757 | 822 |
| E5 输入超过 512 token | 70 | 0 |
| 新版完整 passage 最长 | — | 480 |
| 新版续片数量 | 未记录 | 82 |
| 新版正文覆盖检查遗漏 | 未记录 | 0 |

新的向量矩阵为 822 × 384，编码器独立检查超限数量仍为 0。覆盖检查排除 frontmatter 和作为元数据处理的标题，检查章节正文中的非空白内容。

**零截断不等于检索必然提高。** 片段变短会改变 BM25 的长度统计，也会改变向量表达和候选数量；阶段 9 保留了实际指标变化。

## 运行方式

在项目目录：

```powershell
# 本轮已经生成 token_v1；再次实验请使用新目录，命令会拒绝覆盖已有目录。
.\.venv\Scripts\python.exe -X utf8 -m src.token_chunking --output-dir data/generated/token_v2
.\.venv\Scripts\python.exe -X utf8 -m src.vector_retrieve "RAG 的基本流程是什么？" --chunks-file data/generated/token_v1/chunks.json
```

新建库先写临时目录，完整写完后再更名为目标目录，降低中断导致半套产物的风险。这里还没有实现增量导入；内容 ID 的改进只是为后续增量工作提供基础。

## 练习与参考答案

问：只改原笔记最上方一段，为什么后面片段的 ID 可以不变，但行号、文档指纹和总索引指纹会改变？

答：ID 标识来源位置语义与片段内容，行号标识当前快照中的物理位置，文档指纹标识整篇文本，索引指纹则包含全部 chunk 元数据。它们解决的问题不同。

问：为什么不直接把 E5 的最大长度改成 4096？答：不能靠一个参数让既有模型获得相应的长文本能力。应遵守所用模型约束，或单独选择并验证另一种模型。
