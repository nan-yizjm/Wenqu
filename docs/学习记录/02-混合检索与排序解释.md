# 阶段 2：混合检索与排序解释

## 为什么需要两路

BM25 擅长精确术语匹配，E5 可以找到词面不同但语义接近的内容。例如“基础 RAG 的流程”在向量结果中直接找到第 8 章工作原理；PagedAttention 的精确术语又适合词法检索。两者各有缺口，不能只凭这一对样例认定谁全面更好。

实现位于 `src/hybrid_retrieve.py`。`RetrievalEngine.search` 支持 bm25/vector/hybrid，并返回统一的 `SearchHit`。旧流程需要三元组时，用 `as_result()` 适配，不复制另一套上下文代码。

## RRF 如何工作

同一个原问题分别走 BM25 和 E5，各取前 20 个候选。用 chunk ID 去重，每个通道对同一 chunk 只贡献一次：

```text
RRF(chunk) = Σ 1 / (60 + 通道内名次)
```

名次从 1 开始，没有进入该通道候选窗口则贡献 0。这里 60 是平滑常量，不是“保留 60 个结果”。方法定义可查[Elastic 官方 RRF 文档](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。

例如 A 在 BM25 第 1、向量第 4，分数为 1/61 + 1/64 ≈ 0.032018。B 只在向量第 1，分数约 0.016393。这解释了为什么两个通道都出现的候选往往占优，也解释了一个只在单路出现的真正好片段可能被挤下去。

BM25 分数可能十几，余弦可能 0.89，直接相加会被量纲支配。RRF 使用名次，但也丢弃了原始分差，绝不是完美融合或事实重排序。

## 质量规则只应用一次

沿用已有规则：标题含“待继续拆分”的片段乘 0.35。两路先按原分取候选并融合，再做最终降权。否则如果 BM25 里罚一次、RRF 后又罚一次，就难以解释最终排序。

对单路 bm25/vector，先全库打分再降权；对 hybrid，先限候选窗口再融合降权。因此候选窗口太小，后面再怎么降权也救不回没进入窗口的好证据。

`src.vector_retrieve` 显示原始余弦；`src.hybrid_retrieve --method vector` 显示应用质量规则后的向量排序。比较二者时别把规则引起的变化误认为模型变化。

0.35、20、60 都是显式工程设置，不是本项目已经验证出的最优超参数。本轮没有依据保留集反复调整它们。

## 查看具体分数

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.hybrid_retrieve "一个基础 RAG 系统从用户问题到最终回答通常经历哪些步骤？"
.\.venv\Scripts\python.exe -X utf8 -m src.hybrid_retrieve "PagedAttention 是什么？" --method vector
```

每个结果显示最终分、原分、BM25/向量的通道名次、各自原始分、RRF 贡献、质量系数和原文预览。用 `--no-quality-rules` 可做独立消融，但请保留实验记录，不要只保存分数最好的一次。

实现保留一个重要差异：BM25 使用已有查询预处理，E5 使用完整问题。E5 的同词匹配集合只用于展示，不参与其向量分数。标题/正文词集合在索引初始化时预计算，避免每次查询重复切全文。

## 小练习

问：为什么 RRF 后分数通常比余弦小很多？参考答案：分数定义不同，RRF 是名次倒数的和，不能跨方法比较绝对值。

问：开发集上混合方法最好，能立刻作为默认吗？参考答案：还需看保留集、真实回答和延迟。本轮实测存在保留集退化，所以保留默认 BM25，混合方法作为可用选项。
