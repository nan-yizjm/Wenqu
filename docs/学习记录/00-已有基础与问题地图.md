# 阶段 0：已有基础与问题地图

这是对已有代码和历史输出的回顾，不把以前完成的内容算成本轮新增。

## 已经走过的链路

Markdown 笔记 → 按标题切片 → 关键词/IDF → BM25 → 静态能力守卫 → 上下文打包 → Ollama/DeepSeek → 引用标签检查 → 生成评测。

对应入口是 `src/ingest.py`、`src/retrieve.py`、`src/bm25.py`、`src/query_guard.py`、`src/context.py`、`src/answer.py`。现在你已经不是只阅读理论：你有了一个可运行的系统，以及真实的失败样例。

## 历史问题与经验

1. 英文词被切为双字母：PagedAttention 变成大量无关碎片，英文代码片段很容易得高分。保留完整英文技术词；中文用二元字组。这里的检索 token 和神经模型 tokenizer 的 token 不是同一套东西。
2. 常见问句抢分：IDF、BM25 和查询清理改善词面排序；但删除过宽的中文短语也可能删掉概念。本轮不再针对单题增加删除规则，向量通道直接使用完整原问题。
3. Multi-Query 退化：历史开发集 MRR 从 0.879 降至 0.812，没有改善题。它拆查询；本轮的 Hybrid 是同一完整问题走两种检索器，两者不要混淆。
4. 找到天气示例不代表能回答明天天气：当前守卫是显式短语规则，不是 BM25 统计置信度，也不是通用 OOD 模型。
5. 上下文不等于 Top-5 全文：字符预算、选行与排序会决定最终哪些证据送给生成模型。
6. 标签合法不等于有据可依：模型写了存在的 `[S3]`，依然可能引用错内容。当前校验器只检查编号存在性。
7. 生成评分也会误判：关键词漏写、同义表达、拒答措辞都影响旧规则。但本轮不再围绕这几道题修改评分器；保留原规则和原始回答供复查。

## 本轮先修复的工程问题

- `BM25Index` 的解释性评分在每道题里重复对标题和正文计词频。改为建索引时预计算，查询时查表，不改变 BM25 公式。
- 极小上下文预算可能给部分来源分到 0 个字符，随后 `content[:budget-1]` 变为负切片。现在选择来源时就为每个来源预留内容预算，并跳过空正文。
- 多概念检查曾把三条 MLA 条目误认为覆盖 MLA/GQA/MQA。现在跟踪不同概念标签，重写最多一次，重写后再检查并暴露警告。

注意：最后一项仍只是“英文概念列表格式”启发式，既不覆盖所有中文概念，也不验证事实。它可能把多词术语拆错、误要求列表，后续应改成更稳健的结构化输出协议。

## 怎样定位下一次失败

先问“原笔记有没有答案”，再问“候选有没有答案”，然后看“实际上下文有没有保留答案”，最后看“模型有没有忠实使用证据”。不要一上来换模型，也不要只看汇总分数。

练习：来源文件命中，但具体 chunk 是“待继续拆分的概念”，算完成问答了吗？

参考答案：只能算文件级指标命中。它可能只有术语名，没有原理。要检查 chunk 和实际上下文，才能判断回答依据是否足够。
