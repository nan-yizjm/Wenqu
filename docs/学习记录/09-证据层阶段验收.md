# 阶段 9：证据层改进的实测与交接

日期：2026-09-12。本轮完成 Token 感知切分、Reranker 和完整块上下文三项功能；没有修改原笔记或评分标准，也没有提交、推送 Git。

## 一、数据是否保持可追溯

- 输入是同一份 52 篇文档快照；校验其 SHA-256 与新 manifest 一致。
- 原 757 个片段及其向量缓存保留；原 chunks.json 的 SHA-256 与上一轮报告一致。
- 新语料位于 `data/generated/token_v1/chunks.json`，822 个片段；完整 E5 输入最长 480 token，实际编码检查超限 0。
- 新片段对快照正文的覆盖检查遗漏 0，82 个片段标记为长原文块续片。
- 开发集、保留集、生成集未改题、未改期望。两轮检索报告的题集 SHA-256 一致。

这解决了旧流程的静默截断问题，不代表“长段落语义从此完全保留”。同一原文块被分成不同片段后，跨片关系仍可能丢失。

这里的 Hit 指前 K 名命中任一标注的来源文件，仍不验证具体片段是否足够回答问题。保留集已经在历史讨论中使用过，不当成完全未见的盲测集。

同一套规则守卫使每个集合的 4 个库外问题全部拒绝，库内误拒绝为 0。这不是 Reranker 的拒答能力。

新语料 Hybrid 的开发集 MRR 0.910 低于上一轮旧语料的 0.955；所以“没有截断”与“名次更好”并不等价。切分改变了候选内容、数量及词频统计，不能只看一个总分评价数据处理是否必要。

### 延迟成本

新语料开发集热查询均值：BM25 2.81 ms、Vector 7.29 ms、Hybrid 9.03 ms；加重排后分别约 82.46、87.22、87.67 ms。模型初始化与预热 8.109 秒，单独记录，不算进每道检索题。

固定新语料与 Hybrid 候选，顺序运行三组，每组原来的 18 道生成题，只使用本地 Ollama qwen2.5:7b。

### 保留的具体案例

1. **RAG 流程 gen-010**：三组都提供了检索、上下文组织、生成等流程信息并通过现有规则，相关依据确实进入了上下文。但不应把查询改写、重排序等扩展组件误讲为所有基础 RAG 都必须具备。
2. **MLA/GQA/MQA gen-007**：Blocks 版本给出了三项独立说明；不过 Legacy 重排版本虽然也逐项回答，仍因关键词检查失败。说明格式改善、事实覆盖、字符串评分是三个不同层面。
3. **RAG/Agent/多模态 gen-009**：重排配合 Legacy 时三项均出现；Blocks 版本漏掉多模态，实际只使用了 3 个来源。完整块策略会把大块与小块的预算竞争显露出来，但尚未解决全部覆盖问题。
4. **GRPO/RLVR gen-003**：重排配合 Legacy 的回答把“GRPO 是 PPO 简化变体”扩展成“GRPO 和 RLVR 都是 PPO 简化变体”，却通过旧规则。这是无依据扩展，明确说明标签有效和关键词命中仍会放过错误。Blocks 版本没有这句扩展，但又省略了奖励机制细节并判失败，不能把“更短”直接当成更好。
5. **资料不足 gen-013/014**：三组文字均表达了无法提供具体实现或通信细节，但旧拒答短语规则没有命中。本轮保留机器判分并注明人工观察，不靠添加短语把汇总分数改漂亮。
6. **系统是否变好 gen-012**：仍缺少针对当前知识库系统的完整评测口径，回答泛化到系统功能和回退机制。这个问题没有因增加 Reranker 自动解决。

## 四、工程验收与使用

新增检查覆盖原文坐标、双围栏标题识别、稳定内容 ID、长代码续片、内部空白保留、完整块预算、重排候选边界、负 logit、空查询和失败不静默降级。当前 55 项离线检查通过。

还运行了新语料的完整向量编码、重排相关/无关示例、六路检索比较、三组真实生成以及不调用生成模型的上下文解释入口。天气问题在新完整流程下仍是零次生成调用。

最终复核也验证了 CPU 上的重排示例、连续入口切换与退出、Python 编译检查和 `git diff --check`。CPU/GPU 示例的相关/无关排序一致，分数存在正常的微小浮点差异；没有将这一小样例推广为所有查询跨设备结果完全一致。

为了后续复现实验，生成脚本也增加了运行开始时的源码/数据指纹，以及运行期间输入是否变化的标记。老报告可能没有该标记，不能把缺失当作 false。已有报告仍保留原样。

体验新完整流程：

```powershell
Set-Location -LiteralPath '<项目目录>'
.\.venv\Scripts\python.exe -X utf8 -m src.chat --provider ollama --retriever hybrid --chunks-file data/generated/token_v1/chunks.json --rerank --context-policy blocks
```

看模型将收到什么，不生成答案：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.explain_context "PagedAttention 是什么？它解决什么问题？" --chunks-file data/generated/token_v1/chunks.json --rerank
```

本轮该示例实际为 5 个候选、3 个上下文来源、2188/2200 字符；核心 PagedAttention 列表条目完整保留，但长总览续片仍占据了大量预算。它是下一次讨论上下文多样性时的真实案例，不掩盖掉。

## 五、当前取舍与下一阶段

所有新能力已可用，但保留旧默认入口、旧语料和旧报告。没有根据 8 道保留集问题自动选择一个“最优组合”，没有为总分不涨重复运行直到得到漂亮结果。
