# 阶段 3：接入问答，而不只展示检索列表

## 做了什么

`src/answer.py` 的 RAGAnswerer 依赖统一 RetrievalEngine，默认仍是 BM25，可通过 `--retriever` 切换。`src/chat.py` 是连续使用同一个实例的入口；`src/inspect_report.py` 可以离线查看过去的生成结果。

系统处理顺序：问题 → 静态能力守卫 → 检索 → 上下文预算分配 → 生成 → 可选的一次逐项重写 → 引用标签检查。守卫拒绝天气等请求时，既不加载向量模型，也不调用生成模型。

这轮添加了两类可观测信息：

- 排序：chunk ID、文件、标题、通道名次、原始分、RRF 贡献、最终分。
- 生成：实际上下文、检索器名称、生成调用次数、逐项覆盖检查的最终结果。

这些信息让你能复盘一条回答，而不是只能凭最终文字猜测原因。

## 为什么向量召回后不能照搬关键词选行

假设问题问“内存紧张怎么办”，向量找到了“减少 KV head 数量”。句子没有相同词面，但可能正好有答案。如果再次只保留包含查询词的原文行，会删掉语义检索刚找回的内容。

因此本版 BM25 仍沿用命中词选行；vector/hybrid 使用片段正文，再按统一字符预算打包。每个来源先获得配额，剩余空间按排名分配。预算默认 2200 字符，不是 2200 个 LLM token；该处理不保证证据完整，也不保证和生成模型的窗口精确匹配。

这意味着本轮 BM25 与 hybrid 的生成比较是“检索 + 上下文策略”的端到端比较，不是严格只改变检索器的消融实验。若要归因，下一步需冻结相同的上下文算法再单独比较。

## 使用入口

在项目目录执行：

```powershell
# 单题，默认 BM25
.\.venv\Scripts\python.exe -X utf8 -m src.answer --provider ollama "PagedAttention 是什么？"
# 同一个生成模型，切换混合检索
.\.venv\Scripts\python.exe -X utf8 -m src.answer --provider ollama --retriever hybrid "一个基础 RAG 系统从用户问题到最终回答通常经历哪些步骤？"
# 连续使用，复用已加载索引
.\.venv\Scripts\python.exe -X utf8 -m src.chat --provider ollama --retriever hybrid
```

连续入口中可输入 `:method vector`、`:method bm25`、`:method hybrid`，不影响文件中的默认配置。`--device cpu` 只把 E5 放到 CPU，并不切换 Ollama 的 GPU 使用方式。

DeepSeek 接口保留：把 `--provider ollama` 改成 `--provider deepseek`。注意此时问题和选中的知识库上下文会发往远程 API，并可能产生费用；本轮没有进行该调用，密钥仍由你现有的 `.env` 管理。

## 无需重复调用模型的排查

生成报告现在默认附带检索器和时间戳，不覆盖历史同名结果。运行完成后复制终端打印的实际路径：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.evaluate_generation --provider ollama --retriever hybrid
.\.venv\Scripts\python.exe -X utf8 -m src.inspect_report "data/generated/generation_eval_ollama_hybrid_20260912_133842_095278.json" --case gen-010 --context
```

后一个命令只是读 JSON，不消耗 API。它会显示模型回答、旧规则评分、真实上下文和完整检索轨迹。上面的文件名是本轮留存的实际报告，重跑会生成新名字。

如果想用 PowerShell 自己读，固定使用 `Get-Content -Encoding UTF8 -Raw | ConvertFrom-Json`。历史上的乱码有可能来自读取编码，而非文件内容真的损坏；不要先重存乱码再修复。

## 常见问题清单

| 现象 | 优先检查 | 当前处理 |
|---|---|---|
| 每次都出现 Loading weights | 是新进程还是同一 chat 实例？ | 文档向量缓存不消除模型加载；使用连续入口 |
| 不停重新生成向量 | cache_status 是否 stale？ | 检查语料、标题、revision、包版本是否改变 |
| CUDA 不可用或显存不足 | PyTorch wheel、其他 GPU 进程、E5 与 Ollama 共存 | 可先让 E5 使用 `--device cpu`；不要盲目重装驱动 |
| 新机器缺少模型 | 固定快照是否已缓存？ | vector_retrieve 加 `--allow-download` 一次 |
| 新笔记问不到 | 是否只改了 Vault，却没更新 chunks？ | ingest → 向量查询自动重建 → 重启 chat |
| 引用通过但答案胡说 | 引用片段是否支持该句话？ | 当前只做标签校验，不作事实担保 |
| 天气没有任何检索输出 | 是否被静态守卫提前拦截？ | 这是预期边界，不是索引坏了 |
| 两次回答不同 | 采样、上下文变化、一次修复调用？ | 保留时间戳报告，比较输入与调用数 |

## 小练习

问：在报告中看见 `generation_calls=2`，代表检索执行了两次吗？参考答案：不是，代表第一次生成未满足逐项格式启发式，又基于同一上下文重写了一次。

问：`citation_valid=true` 能排除把 FlashAttention 和 PagedAttention 混在一起吗？参考答案：不能。它只检查引用标签是否属于本次上下文；需要逐句核对证据。
