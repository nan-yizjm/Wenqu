# 阶段 10：把实验参数变成可维护的日常配置

日期：2026-09-12。本文描述已实现的代码，不是功能愿望清单。

## 1. 为什么做这一阶段

之前一次问答需要选择语料文件、模型供应商、检索器、设备、重排和上下文策略。参数越来越长；命令能成功，也不意味着下次会用同一组参数。另一方面，原始 `ingest.py` 中的 Vault 路径是硬编码，更新数据和运行问答容易选到不同的语料。

本阶段新增 `rag.toml`、`src/settings.py` 和 `src/runtime.py`，把“怎么运行”与“核心算法”分开。旧的 `src.answer`、`src.chat` 和评测命令保留原行为，**它们不会自动读取这份新配置**。使用新配置请走 `src.runtime`、`src.index_store`、`src.serve`。

## 2. 配置分工和优先级

| 配置位置 | 负责什么 | 是否适合上传 Git |
|---|---|---|
| `rag.toml` | 笔记目录、索引目录、CPU/GPU、检索和 HTTP 参数 | 可以审阅后上传；注意其中有本机路径 |
| `.env` / 系统环境变量 | 既有模型名、连接地址和 API Key | `.env` 不上传，密钥绝不写进 TOML |
| `vector_retrieve.py` / `reranker.py` | 本阶段固定的模型名、revision 和输入模板 | 固定它们是为了明确向量兼容性 |

本次没有读取或展示你的 `.env` 内容，也没有调用付费 DeepSeek。既有 `.env` 加载规则保持不变：系统环境变量优先，`.env` 用 `setdefault` 补缺失项。新 TOML 参数则由 `--config` 指定的文件决定，不再用一堆互相覆盖的命令行开关。

Embedding 暂不支持随意换一个模型名就运行：不同模型的 query/passage 前缀、token 上限和训练方式可能不同，需要明确实现适配。生成模型名继续沿用既有 `OLLAMA_MODEL` / `DEEPSEEK_MODEL` 配置。

## 3. 已处理的常见问题

### Windows 反斜杠和相对路径

TOML 中用单引号写 Windows 路径，避免把 `\n` 等当转义。所有相对路径以**配置文件所在目录**为基准，而不是终端当前目录。移动一份配置文件，也会改变它的相对路径基准。

```toml
vault_dir = '<你的知识库目录>'
store_dir = 'data/generated/index_store'
device = 'cuda'
```

`python -m src.runtime` 这个模块命令本身仍需要在项目目录执行，或正确配置 Python 包搜索路径；“数据路径不受 cwd 影响”不等于“任意目录都能找到 src 包”。

### 错误参数提前失败

`Settings.__post_init__` 检查选择值、类型和相互约束，例如：

- `rerank = false` 是布尔值；`rerank = 'false'` 是字符串，会报错。
- `top_k <= candidate_k`；启用重排时还要求 `top_k <= rerank_top_n <= candidate_k`。
- token 上限、重叠、超时、端口、问题长度有范围。
- 索引目录不允许放在扫描的笔记目录里，避免派生数据被反复导入。
- 未知字段不被静默忽略。`api_key` 放错到 TOML 时，只报告字段名，不显示字段值。
- HTTP 本版仅允许 `127.0.0.1`，修改成 `0.0.0.0` 会被拒绝；公开部署另做权限设计。

这些检查不解决模型答案质量，但可以把“GPU 加载十秒后才发现参数写错”变成启动前的明确错误。TOML 使用 Python 标准库 [tomllib](https://docs.python.org/3/library/tomllib.html) 读取，不额外引入配置框架。

## 4. 现在的日常工作流

在项目根目录的 PowerShell 中：

```powershell
# 第一次构建，或修改笔记后更新。没有变化时很快返回 unchanged。
.\.venv\Scripts\python.exe -X utf8 -m src.index_store build

# 确认当前发布了哪个版本
.\.venv\Scripts\python.exe -X utf8 -m src.index_store status

# 连续提问，输入 :quit 退出；每道问题独立，不拼接对话历史
.\.venv\Scripts\python.exe -X utf8 -m src.runtime

# 单次回答，包含版本、来源、标签校验和耗时
.\.venv\Scripts\python.exe -X utf8 -m src.runtime "PagedAttention 是什么？"
```

想改参数直接编辑 `rag.toml`。更改检索器、上下文策略等运行参数，重启运行时即可；更改分片参数，要重新 `build`。更改笔记目录却没重新构建时，运行时会拒绝使用另一目录的旧索引。

默认组合是 Ollama + hybrid + blocks；重排关闭。不是宣称这个组合在所有问题上最好，而是提供一条可用的服务路径，同时保留旧实验基线。想体验重排，将 `rerank = true`；CPU 重排默认用于把可选工作与生成模型的 GPU 占用分开。

## 5. 沿哪几个函数读代码

1. `load_settings`：读取配置、检查未知字段、解析路径。
2. `Settings.__post_init__`：检查字段之间的约束。
3. `IndexStore.current`：读取并验证当前索引指针。
4. `RAGRuntime.__init__`：固定该版本，建立 RAGAnswerer，预加载需要的检索模型。
5. `RAGRuntime.answer`：复用模型，返回答案和版本；不会每题重新加载 E5。

新版本目录的向量加载使用 `read_only=True`。若模型或依赖升级导致缓存不兼容，运行时应报错让你构建新版本，不能把历史版本里的矩阵悄悄覆盖。

## 6. 小练习与参考答案

**题 1：把上下文预算由 2200 改成 2600，是否需要重新编码全部笔记？**

参考答案：不用。这是生成上下文预算，不影响 E5 的 passage 输入；重启运行时应用新配置即可。它也不是精确的生成模型 token 预算，仍需警惕长问题和总上下文上限。

**题 2：修改 max_tokens 后，旧向量能否继续用？**

参考答案：要重新分片构建新版本。但分片后输入字符串完全不变、模型配置也一致的片段仍能复用旧向量；不是简单地把所有缓存保留或全部丢掉。

**题 3：服务启动后修改 TOML，为什么本次答案没变化？**

参考答案：运行时启动时读取一次配置，并固定索引版本。本版没有热更新，这是为了避免一条请求计算到一半换模型或换语料。修改后重启。
