# 阶段 15：从 Attention 到可以训练的语言模型

日期：2026-09-12。接续阶段 14。本阶段实现模型和数据，实际训练与断点恢复见 [阶段 16](16-训练循环与断点恢复.md)。

## 1. 本次新增什么，哪些东西没变

现在有了一个从随机权重开始的字符级 decoder-only 语言模型：输入字符 ID，输出下一字符的词表分数，训练后可以续写有限的短文模板。

| 文件 | 从哪里开始读 | 职责 |
|---|---|---|
| `src/tiny_decoder.py` | `DecoderBlock → TinyDecoder.forward → generate` | 位置编码、残差、前馈层、词表输出、多层缓存生成 |
| `src/training_data.py` | `synthetic_documents → prepare_data → make_windows` | 数据来源、分组切分、训练词表、下一 token 标签 |
| `tiny_lm.toml` | `[model]` 与 `[training]` | 独立教学配置，不与 `rag.toml` 混用 |
| `src/train_tiny_lm.py` | `next_token_loss → evaluate → train` | 下一章讲解的训练和恢复流程 |

复用了上一阶段手写的 `CausalSelfAttention`，没有用一个现成的完整 Transformer 隐藏内部结构。没有下载新模型、购买算力、调用远程生成 API，训练语料也不是你的 Obsidian 笔记。原 RAG 继续使用 Qwen；这个小模型没有接管知识库助手。

本机使用 Python 3.14.3、PyTorch 2.13.0+cu132、RTX 5060 Laptop GPU，沿用已有环境，没有重新安装 CUDA 或修改系统环境配置。

## 2. 单个 Attention 为什么还不是语言模型

阶段 14 输入的是随机隐向量，输出还是隐向量。要生成文字，需要解决三个连接问题：文字怎么进来、顺序怎么表示、隐向量怎么变成下一个字符。

实际训练的形状是：

```text
字符 ID [16, 96]
  → token embedding + learned position embedding
隐向量 [16, 96, 128]
  → 2 个 DecoderBlock
  → final LayerNorm
  → vocab projection
logits [16, 96, 140]
  → 与右移一位的标签计算交叉熵
```

16 是 batch size，96 是训练窗口，128 是隐藏维度，140 是本次字符词表大小。输出的最后一维不是 embedding 维度，而是“每个候选字符的分数”。

`logits[b, t, :]` 用来预测位置 t 后面的字符。logits 可以为负，也不要求总和为 1；训练直接交给交叉熵，不要先调用 softmax 再送进去。本机文档字符串与 [PyTorch CrossEntropyLoss 说明](https://docs.pytorch.org/docs/main/generated/torch.nn.CrossEntropyLoss.html) 已核对；在线 main 文档可能比本机版本更新。

## 3. 一个 DecoderBlock 具体做了什么

本版使用 Pre-LN：先归一化，再进入 Attention 或前馈层，再加回原来的 x。

```python
x = x + dropout(attention(layer_norm(x)))
x = x + dropout(ffn(layer_norm(x)))
```

不要直接把这两行当成现有函数的完整签名：实际 Attention 还返回缓存，代码中先拆开返回值。

- Attention 让当前位置从允许访问的历史位置聚合信息。
- FFN 对每个位置分别做 `128 → 512 → GELU → 128` 的非线性变换，不负责跨位置通信。
- 残差相加要求两侧形状一样；它让子层学习对当前表示的修正，也提供直接的梯度通路。
- LayerNorm 沿隐藏维度工作，不是把整个 batch 的所有字符混起来统计。
- Dropout 在训练时启用，在验证和生成时关闭。本实现没有 attention probability dropout，只有输入和残差分支的 dropout。

这是一种用于理解依赖关系的小模型结构，不是 Qwen 架构的逐项复刻。没有实现 RoPE、RMSNorm、SwiGLU、GQA、权重共享或 MoE。

## 4. 位置编码与 KV Cache 的连接

字符 embedding 表达字符身份；本版另外学习一个位置表 `Embedding(96, 128)`，给每个位置加入一个向量。

完整输入 5 个位置，用位置 0～4。已缓存这 5 个位置，再追加两个 token，必须用位置 5、6，不能重新用 0、1。

各层独立保存自己的 K/V；缓存层数和长度必须一致，不能把第一层缓存拿给第二层。模型的缓存分支要求 eval 且关闭梯度，训练仍一次计算整个窗口，不复用推理缓存。

已经验证：相同模型、相同输入下，一次完整计算和多层缓存追加的 logits 在浮点容差内一致；修改未来 token 不会改变过去位置输出。

超过 96 的位置窗口时明确停止或报错，不偷偷裁剪缓存然后重置位置。训练窗口也为 96，避免配置允许的位置范围大于本次训练实际覆盖的位置范围。即便所有位置都参与过训练，也不代表已经学会可靠的 96 字长程推理。

## 5. 为什么先用来源明确的合成短文

本项目直接在 `synthetic_documents()` 中编写两种叙事模板，再组合：4 个人物 × 4 个地点 × 4 个工作任务，共 64 个情景组，每组两种表述，共 128 篇短文。

它们描述“检查材料 → 执行整理任务 → 记录问题 → 保存结果”。这样能很快观察随机模型如何学会字词搭配和句式，也不需要先处理数据许可、网络下载或私人信息。

代价也明确：模板非常重复。即使保留了一些人物、地点、任务组合，验证集与训练集仍共享大量句式。因此这是训练管线的教学数据，不是通用中文能力基准。

没有声称“未用于训练的文档 = 所有内容都未见过”。相同模板会使验证任务很容易，这个限制写入了数据清单。

## 6. 先分组，再建词表，最后切窗口

数据处理顺序：

1. 检查 `id / group_id / text`，拒绝重复 ID 和规范化后完全相同的文本。
2. 根据 seed 和 group 的哈希稳定划分训练/验证；同一情景的两个改写必须在同一侧。
3. 只用训练文本建立字符词表；验证里未见过的字符变为 `<UNK>`。
4. 给每篇文档单独加 BOS/EOS。
5. 在各自的 split 内切训练窗口，窗口不跨文档。

如果先切窗口再随机划分，同一篇文章相邻、重叠的内容可能同时进入训练和验证。如果只按文档 ID 随机划分，同一情景的两个近似改写也可能跨两边。本版分组避免后一种直接泄漏，但没有实现通用近重复检测器，仍需正确给自备数据定义 group。

实际数据版本：`data/generated/tiny_lm_data_v1/`。

| 项目 | 训练 | 验证 |
|---|---:|---:|
| 情景组 | 51 | 13 |
| 文档 | 102 | 26 |
| 含 BOS/EOS 的 token 数 | 11296 | 2880 |
| 有效下一 token 目标数 | 11194 | 2854 |
| 96-token 窗口数 | 204 | 52 |

词表共 140 项，其中 4 个特殊符号；本次验证 UNK 数为 0。这个 0 只说明验证字符都在训练词表中，不说明任意中文都支持。

`dataset.json` 保存 split、文档和编码；`vocab.json` 保存 ID 映射；`manifest.json` 保存来源、切分规则、统计和文件 SHA256。加载时核对哈希与分组交叉，数据改动后不能继续冒充原来的实验。

## 7. 输入和标签为什么要错开一位

假设一篇文档编码后是：

```text
[BOS, 小, 林, EOS]
```

用 block_size=2，会得到：

| 窗口 | 输入 x | 目标 y |
|---|---|---|
| 1 | `[BOS, 小]` | `[小, 林]` |
| 2 | `[林, PAD]` | `[EOS, -100]` |

每个有效目标只计算一次；窗口间重复的边界字符是必要的输入，不意味着同一个目标重复算损失。EOS 也要预测，BOS 不需要从上一篇文章预测出来。

输入 PAD 的 ID 是 0；标签 -100 不是词表 token，而是 loss 的忽略标记。不能把标签也填成 0 后不加区分地训练，否则模型会花力气学习大量“输出 PAD”。

本版严格右填充，真实位置只看过去，所以真实 token 不会读到尾部 PAD；PAD 位置的损失被忽略。这个前提下不额外使用 padding attention mask。若换成左填充、双向注意力或多个样本拼接，必须重新处理 mask，不能照搬。

窗口不跨文档，但一篇长文会分为多个独立窗口。第二个窗口看不到前一个窗口的完整历史，位置也重新从 0 开始；这是当前简化的数据策略，不是有状态的跨窗口训练。

## 9. 遇到的问题与处理边界

- Attention 输出不是词表分数：补上 embedding、完整 block 与 lm_head，避免把“有注意力”误称为“能训练语言模型”。
- 加入位置编码后，缓存还可能形状正常但语义错位：追加位置使用 past offset，并核对多层、多 token 追加。
- 数据尾窗大量填充：移位标签后单独标记忽略值；验证按有效目标计数。
- 同题材改写可能污染验证：以情景 group 切分；仍承认模板共享，不宣称完全消除语义泄漏。
- 生僻字符不可表示：保留 UNK，而不是借验证集或随手扩词表改变旧模型的 ID 含义。

前四项是实现时明确处理的工程风险，不是宣称运行过程中都出现过异常；实际生成失败和恢复实验的直接证据在阶段 16。

## 10. 练习与参考答案

**练习 1：batch 改为 8，窗口改为 64，词表不变，logits 什么形状？**

答案：`[8, 64, 140]`。改 batch 不会改变参数个数；扩词表或隐藏维度会改变参数结构。

**练习 2：为什么“把 y 设为 x”不是下一字符训练？**

答案：目标变成复现当前位置。因果 Attention 可以读当前位置，再叠加残差，模型可能学会复制，而不是根据前缀预测后续。

**练习 3：验证损失低，能否说明模型从没见过类似文本？**

答案：不能。文档 ID 不重复与模板不重复是两回事。本数据有分组隔离，但仍共享句式，不能从损失推断通用能力。

**练习 4：追加一个未见过的字符到旧 vocab.json，继续加载旧 best.pt，行不行？**

答案：不能直接这样做。embedding 和输出层大小、字符 ID 映射、数据指纹都有关联；需要明确的新模型/数据迁移方案，不能静默混用。
