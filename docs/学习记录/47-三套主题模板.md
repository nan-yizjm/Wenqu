# 学习记录 47：三套主题模板（浅/深各一）

> 日期：2026-09-19。使用者要"3 套模板，每个模板都有浅色和深色界面"。做法是**把颜色从规则里彻底抽出来**：styles.css 从 2 个 token 块扩成 6 个（默认浅 + 默认深 + 3 套模板 x 浅/深），同时把 73 处硬编码圆角收敛成 `--radius-*` 刻度——模板的"性格"由色板与形状共同表达，只换强调色的话三套看起来会是同一个东西的调色版本。

## 一、三套模板的定位

| 模板 | 色板 | 圆角刻度 (xs/sm/md/lg) | 定位 |
| --- | --- | --- | --- |
| 纸墨 `paper` | 米白纸感 · 深绿 `#244d3e` | 5 / 9 / 13 / 20 | 默认；安静的阅读工作台（原风格精修） |
| 石板 `slate` | 冷灰蓝 · 靛蓝 `#2d4a7c` | 4 / 6 / 9 / 12 | 信息密集的工具感，边框更硬、圆角更利 |
| 暖砂 `sand` | 暖米底 · 赤陶 `#9a5b32` | 6 / 12 / 18 / 24 | 更松弛的纸感，圆角更圆 |

深色版本各自成对（纸墨→墨夜绿、石板→深蓝灰、暖砂→暖黑棕），浅深是两个独立轴：`theme`（system/light/dark）管明暗，`theme_template` 管皮肤，互不干扰。

## 二、层叠顺序是可推导的，不是试出来的

六块的选择器与顺序有明确理由：

```css
:root{...}                                        /* 纸墨浅色：无 data-template 时也成立（首屏兜底） */
html[data-theme="dark"]{...}                      /* 纸墨深色：特异性 (0,2,1) */
html[data-template="slate"]{...}                  /* 石板浅色：同特异性、靠顺序压过上一块 */
html[data-template="slate"][data-theme="dark"]{...}  /* 石板深色：特异性 (0,3,1) 最高 */
html[data-template="sand"]{...}
html[data-template="sand"][data-theme="dark"]{...}
```

关键推论：`html[data-theme="dark"]` 在选 slate/sand 时**也会命中**，所以①同特异性的浅色块必须排在它后面（后者胜），②深色块靠更高特异性胜。把纸墨深色改成 `:not([data-template="slate"]):not(...)` 反而会因特异性升到 (0,4,1) 压过所有模板深色块——**这是这次唯一差点踩进去的坑**。

## 三、选择与持久化

- 设置项 `theme_template`（`app.py` 白名单 + 默认 `paper` + validator：只认三个值，`neon` 之类一律 422）。落库而不是只存 localStorage：皮肤跟着数据走，换机器/重装后还在。
- 前端 `lib/theme.ts`：`applyTemplate` 写 `data-template`（CSS 级联完成换肤，**不需要 React 重渲染**）；`bootstrapAppearance()` 在 `main.tsx` 的首次 render 之前按 localStorage 把 `theme` 与 `template` 摆好——主题的权威来源是启动后才会拿到的 settings，不先摆好每次刷新都会闪一下。
- 设置页：模板选项带**色板样本**，样本色以数据形式写在 `TEMPLATE_OPTIONS.swatch.{light,dark}` 里、内联进样式。为什么不在 CSS 里做：页面上生效的变量只能是当前模板的值，而样本必须显示"那套模板"的颜色；样本随当前实际明暗切换（`useResolvedTheme` 解析 system 并跟随系统变化），深色界面里看到的就是切过去的深色样子。design token 门禁只守 `styles.css`，JS 里的样本色是数据不是样式。

## 四、顺手修掉的缺陷：浅色下的遮罩是透明的

`--scrim` 原来只有深色块定义，而 `.picker-backdrop{background:var(--scrim)}`（应用内文件夹选择器的遮罩）在浅色模式下取到**未定义变量**——遮罩透明，弹层背后的页面清清楚楚。现在三套模板的浅色块都有各自的 scrim，门禁的"六块键名一致"顺带把这类不对称钉死。

## 五、门禁升级（`scripts/check_css_tokens.ps1`）

原来只认 2 个块、只查"深色缺浅色的键"。现在四条：

1. 块数必须恰好 6；2. 块外无颜色字面量；3. **六块键名完全一致**（少一个键，切到那套皮肤时该属性会串回上一套的值，界面上只是"颜色有点怪"，肉眼几乎无法定位）；4. `:root` 的键都被 `var()` 用到。

脚本是 PowerShell（本环境跑不了），用 Python 做了完整等效；**等效脚本第一版只匹配到 2 个块**——正则是 `(?:...|html\[data-template="[a-z]+"\]\{|...)\s*\{`，分支里带了 `\]\{` 又要求尾部 `\s*\{`，等于要求两个 `{`。诊断靠的是脚本自己那句"块数应为 6，实际 2"——**断言把静默错误变成了明面错误**，这就是当初坚持把块数写进断言的理由。

## 七、边界
