# 31：收藏、反馈与 Markdown 导出

日期：2026-09-15

## 1. 用户任务

本阶段让问答结果从“看完即走”变为可整理成果：

```text
完整回答 → 收藏 → 修改标题/备注 → 回看证据 → 导出 Markdown
               └→ 本地反馈：有帮助 / 遗漏 / 引用不对 / 回答不对
```

未完成、失败、没有可核对来源的回答不能收藏，避免把半段输出或无证据文本沉淀为知识。

## 2. 数据模型与快照

数据库升级到 schema 4：

- `favorites` 复制问题、回答、标题、备注、provider、model、index version 和生成时间；
- `favorite_sources` 复制每个来源的文档版本、章节、行号/页码和预览；
- `answer_feedback` 按 message ID 保存一条本地反馈，再次反馈会更新原记录。

收藏不只是指向消息。如果只保存 `message_id`，未来删除会话、迁移数据或改变来源关系时，成果会变成空壳。复制必要字段使收藏成为独立快照，同时仍保留原 message ID 供追踪。

同一回答重复点收藏是幂等操作，返回已有收藏，不产生重复条目。

## 3. 导出格式

导出文件固定 UTF-8 和 LF，可直接放入 Obsidian：

```markdown
# 收藏标题

> 问题：原问题

## 备注

用户备注

## 回答

带 [S1] 的回答

## 来源

- [S1] 文件 — 章节（第 5–5 行）
```

末尾另存生成时间、模型和索引版本。文件名过滤 Windows 的 `< > : " / \\ | ? *` 和控制字符，避免用户标题导致导出失败。导出先写临时文件再替换，防止中途退出留下半个 Markdown。

## 4. 反馈边界

四类反馈默认只进入本机 SQLite：

- `helpful`：回答有帮助；
- `missing`：重要信息遗漏；
- `citation_wrong`：引用定位或支持关系不对；
- `answer_wrong`：回答结论不对。

反馈目前不发送、不自动训练、不直接改变排序。它是阶段 33 复盘的事实记录，不是假装已经存在的在线学习系统。

## 5. 接口与页面

新增：

```text
GET/POST       /api/v1/favorites
GET/PATCH/DELETE /api/v1/favorites/{id}
GET             /api/v1/favorites/{id}/export
POST            /api/v1/feedback
```

问答页的完整、有来源回答显示收藏和四类反馈操作。收藏页左侧是成果列表，中央编辑标题/备注并阅读答案，右侧复用阶段 29 的来源阅读器。导出使用普通下载链接，不要求用户选择目标笔记库，也不会自动修改 Obsidian 文件。

## 6. 验收

自动检查覆盖：

- 收藏复制回答及 Markdown 行号来源；
- 同回答重复收藏不重复；
- 编辑标题和备注；
- Windows 禁止字符不会破坏导出文件名；
- 导出正文是 UTF-8，包含回答、来源和定位；
- 反馈合法类型、非法类型和幂等更新；
- 停止回答无法收藏；
- 删除收藏不删除原回答。

真实浏览器使用本机 Ollama 完成：生成 RAG 回答 → 收藏 → 标记“有帮助” → 打开收藏页 → 标题改为“RAG 在线流程复习” → 写备注 → 打开 `[S2]` 第 5 行证据 → 下载 `RAG 在线流程复习-….md`。浏览器控制台 0 error、0 warning。

## 8. 手动练习与参考答案

1. 为什么收藏要复制来源，而不是每次打开时重新检索？
2. 为什么 `message_id` 对反馈有用，但不足以单独构成收藏？
3. 为什么首版只下载 Markdown，不直接写进用户 Vault？
4. 为什么反馈不能自动成为训练数据？

参考答案：

1. 重新检索会受文档更新和排序变化影响，不能保证还是回答当时的证据；收藏应保留可复核的历史快照。
2. 反馈描述的正是某次回答，所以 message ID 是稳定对象；收藏还要独立保留可读内容，不能依赖会话永远存在。
3. 自动写入涉及目录权限、重名、覆盖、同步冲突和用户信任；下载是可见、可撤销、边界清楚的首版行为。
4. “有帮助”不等于每句话都正确，“回答不对”也没有给出正确答案；未经复核直接训练会放大噪声和隐私风险。
