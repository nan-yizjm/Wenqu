# 37 · 信息图与无头渲染

P4（图片产出）的交付记录。**这一篇的重点是"图是画出来的，不是生成出来的"**——以及一个只有眼睛能发现的缺陷。

## 一、交付了什么

| 层 | 文件 | 说明 |
|---|---|---|
| 渲染 | `src/product/headless.py` | 本机 Edge / Chrome 发现 + 无头截图；`screenshot()` 返回渲染器、耗时、字节数、像素 |
| 版面 | `src/product/infographic.py` | `build_model()` 把产出记录算成图的内容**与高度**；`render_html()` 填固定模板 |
| 导出 | `src/product/studio.py` | `export_infographic()`：写 HTML → 起浏览器 → 落 PNG + `render.json` |
| 接口 | `src/product/app.py` | `POST/GET /artifacts/{id}/infographic`、`GET /artifacts/{id}/infographic.png` |
| 界面 | `web/src/StudioPage.tsx` | `InfographicCard`：导出按钮、图、耗时/尺寸/渲染器、下载、降级提示 |
| 验收 | `scripts/ui_acceptance.cjs` | 第 11 步：真点导出、等图真的加载出来、验尺寸与下载 |

**没有新表、没有新迁移、没动 `artifacts.kind`。** 信息图要的东西全都在库里：来源分布、章节结构、回链命中率——`StudioService.get_artifact()` 一次就给全了。所以 `build_model()` 是纯函数，不碰数据库、不碰模型、不碰网络。

导出物与产出**同生命**：删一条产出，`infographic.html` / `.png` / `render.json` 一起删（`delete_artifact` 里顺手做掉）。验收跑完 `exports/` 是空的，不留幽灵文件。

## 二、三个设计决策

**1. 信息图是"导出器"，不是第三种产出类型。**

一开始想过给 `artifacts.kind` 加个 `'infographic'`。放弃了，两个理由：

- `kind` 上有 `CHECK(kind IN ('guide','mindmap'))`。加值要**重建表**，而 `artifact_sources` 对 `artifacts` 有 `ON DELETE CASCADE` 外键——重建表就得把那串外键一起搬。为了一格枚举值动整张表的结构，风险和收益不成比例。
- 更根本的是：信息图**不是跟指南、导图并列的一种"内容"**。指南和导图是模型/算法产出的东西，信息图是**把已有产出画出来**。把它塞进 `kind` 会让"产出列表"里出现一种点不开正文的条目。

所以它落在 `exports/` 目录里，跟着产出走，不进产出列表。**代价**：一份产出只能有一张信息图（同名覆盖）。真要"同一份产出导出多种版式"，那得先有版式这个概念——现在没有，不假装有。

**2. 版面高度是算出来的，不是量出来的。**

所有文本行 `nowrap + ellipsis`（**永不换行**），每个区块高度在 CSS 里写死，`build_model()` 把这些常量加起来就是实际内容高度。于是 `--window-size` 给多少就正好多少像素：**不裁切，也不拖白边**。

这条契约有个副作用：CSS 里写的高度常量和 Python 里的版面常量是**两份真相**，改一份忘另一份就会裁掉一行或留一片空白，而且不会有任何报错。所以有测试盯着它（`test_style_heights_agree_with_the_layout_constants`），短路验证里也专门有一条改 CSS 高度的。

**3. 渲染不出来不算故障。**

本机没有 Edge / Chrome 时，`export_infographic()` 返回 200，`render.status = 'unavailable'`，但**HTML 一定已经导出**——用户可以用自己的浏览器打开它，或者自己打印成图片。界面用 warn 色而不是 danger 色说明这件事，并给出 HTML 路径和"把 `OBSIDIAN_RAG_BROWSER` 指向 Edge/Chrome"这个自救方法。

一个能自救的功能不该被显示成故障。这与 P2 的"联网失败要明确写出'本次未能联网'"是同一条口径。

## 四、只有眼睛能发现的那个缺陷

**图能出、测试全绿、验收全过，但副标题被自己吃掉了。**

信息图的副标题是一整行 `nowrap`：`主题：… · 生成于 … · 索引 … · 来源层级 笔记 12 · 联网 0`。第一版把两个原值直接贴上去：

- `created_at` 是 `2026-09-18T08:55:08.198763+00:00`（**32 字符**，秒以下小数位和时区在图上没有任何信息量）
- `index_version` 是 `idx_` + 32 位十六进制（**36 字符**）

两段加起来 68 个字符，把整行占满，渲染出来结尾是 `… 来源层级 …`——**有信息的那一半（这份产出的来源里有几条出过网）反而看不见了**。

抓到它的方式很朴素：**把导出的 PNG 打开看**。没有任何测试会发现这件事——`assertIn("来源层级 笔记 1 · 联网 1", html)` 照样通过（子串还在 HTML 里，只是渲染时被省略号吃掉了）。这是我的验证清单里"组件测试与断言都不等于交付物可用"的第 N 次复现，只不过这次绕过测试的是 **CSS 的溢出**而不是页面挂载。

修法与产出详情页对齐（短写法 + 原始值仍留在模型里），并补了一条先验证会挂的测试：断言完整的 36 位哈希**不在** HTML 里、而短写法在。短路验证里加了第 13 个点专门打它。

```python
# 副标题是单行不换行的，长的会挤掉排在最后的「来源层级」。
subtitle = (f'主题：{model["topic"] or "未记录"} · 生成于 {model["created_label"]}'
            f' · 索引 {model["index_label"]} · 来源层级 {model["stats"]["origin_text"]}')
```

修完重渲染，整行完整可读：`主题：Llama3-2407.21783v3.pdf · 生成于 2026-09-18 08:58 · 索引 idx_a5eb · 来源层级 笔记 12`。

## 五、踩过的坑

1. **无头 Chrome 按扩展名判格式。** 原子落盘的习惯写法是 `x.png.tmp` → 报 `Unsupported screenshot image file type: .tmp`，**根本不出图**。改成 `.x.staged.png`，成功后再 `replace`。
2. **`Path.as_uri()` 不接受相对路径。** 测试传相对路径直接 `ValueError`。`render_args()` 内对所有路径统一 `resolve()`。
3. **每次渲染必须用一次性 `user-data-dir`。** 否则命令行会被转交给使用者**正在跑的**浏览器实例，`--screenshot` 被忽略，脚本以为成功。副作用是 TEMP 里会攒 profile（`ui_acceptance.cjs` 早就为同一件事写过注释）。
4. **Windows 下 `subprocess` 要 `CREATE_NO_WINDOW`。** 不加的话每导一次图弹一个黑框；一个"导出图片"的功能不该闪黑框。
5. **超时的文案和测试断言是耦合的。** 代码里写"超过 N 秒仍未完成"、测试断言 `"超时"`，两边措辞不一致就挂——这是好事，说明断言在测真实字符串，但改文案要同时改测试。
6. **导图那条记分条最初根本不渲染。** 导图没有命中率，`_backlink()` 返回空串，整段 HTML 消失。改成**两种产出都占位**（导图写"不适用 + 为什么"），顺带让两种产出的高度算术不用分叉。
7. **Starlette 的 `Content-Disposition` 按 RFC 5987 百分号编码中文文件名。** 断言"文件名原样出现"会挂；改成断言 `attachment` + `filename*=` + `.png`。
8. **CSS 不能写在 f-string 里**（花括号要转义）。动态尺寸走 CSS 自定义属性 `--page-width/--page-height`，样式表里一个花括号都不用转义。
9. **Python 的 `bytes` 字面量不能含非 ASCII。** `b"这不是 PNG"` 是语法错误，写 `"这不是 PNG".encode()`。

## 六、短路验证

13 个后端点 + 5 个前端点，**全部"如期挂掉"**才算数（`.workbuddy/shortcircuit_infographic.py` / `..._web.py`）。挑几个说明它测的是什么：

- 忽略 `OBSIDIAN_RAG_BROWSER` → 降级时唯一的人工出口失效
- 退码 0 就当出图成功 → 不校验输出是不是 PNG
- 漏掉 `--force-device-scale-factor` → 图片像素少一半
- 去掉一次性 `user-data-dir` → 撞上使用者正在跑的浏览器
- 找不到浏览器时抛异常而不是降级 → 用户拿不到任何东西
- 删产出时留下导出物 → `exports/` 里出现幽灵文件
- 图片接口忘了区分预览与下载 → 预览变成强制下载
- 副标题贴上完整哈希 → 把"来源层级"挤掉

新写的测试要**先验证它会失败**（临时短路，确认挂掉再还原），否则可能是跟着实现写出来的空壳。

## 七、还没解决

1. **只有 PNG。** PPTX 仍在计划外（`docs/新功能实施计划-2026-09-18.md` 里写着"待 P4 之后再议"）。图像生成模型也没引入——不需要，信息图的数据本来就在库里。
2. **图是像素，不能选中、不能被检索。** 内容和 HTML 是同一份数据，但下游（搜索、引用）看不到图里的字。这张图是给人看的，不是给机器读的。同理，图里的 `[S1]` 编号**不可点击**——要追溯得回到产品里点来源面板。
3. **字体依赖本机。** 版面用的是系统 UI 字体，换一台没有该字体的机器，字符宽度会变，`nowrap` 行的截断位置就变了。高度不受影响（行高是写死的），所以不会裁切，但**断在哪里会变**。
4. **浏览器实测范围（09-19 更新）**：Edge（909 / 744 ms 两次）与 **Chrome（955 ms，走完整产品链路的补测）** 都已验过、结果一致；代码优先找 Edge、回落 Chrome，`OBSIDIAN_RAG_BROWSER` 可覆盖。其它浏览器与其它 Edge 版本仍未验——`render.status='unavailable'` 的降级路径就是为它们准备的。
5. **版面里的截断只有"行"这一级是诚实的。** 超出 `MAX_DOCUMENT_ROWS` / `MAX_HEADING_ROWS` 的行会如实写"另有 N 未画出"；但**行内**的标签串溢出（例如一篇文档贡献 12 个片段时，`S1 S2 … S12` 会被省略号吃掉）**不报也不说**。第一版真实渲染里就是这个样子。
6. **产物不进任何清单。** `exports/` 里的文件只有"删产出连带删"这一条生命周期规则，没有"信息图列表"、没有"最近导出"。要重新拿一张，得回到那份产出再导一次。
