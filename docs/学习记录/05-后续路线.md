# 阶段 5：后续路线（计划，不是已完成功能）

进度更新（2026-09-14）：证据层首版见 06～09；配置、版本化数据与本机 HTTP 见 10～12；CPU/GPU 部署实验、手写 Attention 与 KV Cache 见 13～14；小型 Decoder、训练恢复和泛化挑战见 15～17；RAG 行为 SFT、QLoRA 训练和同基座比较见 18～19；adapter 真实 RAG、常驻服务、流式取消、生成 token 预算、有界 FIFO、阶段监控、CPU 容器基线、供应链清单与索引恢复见 20～27。本页保留原路线，避免把“已做过首版”和“已彻底解决问题”混为一谈。

## 现在真正的下一步

1. 数据与泛化（首个受控实验已在 17 完成）：已证明原验证低损失主要覆盖模板内任务，后续数据版本必须配独立测试。
2. 有目标的 SFT（首版已在 18 完成）：目标限定为依据给定证据引用、拒答、识别冲突、多跳和抵抗证据内指令；逻辑 messages、chat template 与 response-only loss 已打通。
3. LoRA/QLoRA（首轮已完成）：固定 Qwen2.5-1.5B commit，在 8 GB GPU 上完成 adapter 训练、保存、重载和受控前后对比；分别保留已观察回归集和训练前冻结的技术 holdout。
4. 回到系统（首轮已完成）：adapter 已接入真实索引和独立常驻服务；已比较格式遵循、事实依据、启动/热请求、显存与退化题，结论是不替换当前 Ollama Qwen。
5. 流、取消、token 预算、背压与监控（首轮已完成）：模型层 stopping criteria、NDJSON、断线清理、真实 Qwen prompt 计数、完整块重打包、默认关闭的 1-active + N-waiting FIFO，以及不保存正文的分阶段滑动窗口均已实测。
6. 容器化（CPU 基线已完成）：Linux 容器运行 CPU E5 与 RAG 服务，复用宿主 Ollama；只读 Vault、独立索引、loopback 端口、非 root、显式模型缓存和内容审计已真实运行。
7. 供应链与可恢复性（首轮已完成）：公开清单省略私人路径/正文，索引备份使用成员白名单和双层哈希，只恢复到新目录；已验证内容篡改拒绝及恢复后真实问答。镜像签名、漏洞扫描、远端加密副本和 RPO/RTO 尚未实现。

下一步是“发布候选验收”：把单元检查、配置/索引身份、后端就绪、关键问答、隐私与制品清单组合成有明确通过/阻断结果的一次运行；不直接跳到 Kubernetes 或未经验证的 GPU adapter 镜像。

下一阶段停止点：交付一份新的数据版本和可解释的训练/生成对比，能指出“数据里缺什么、模型学了什么、为什么仍会失败”。不要求把整个微调路线一次完成，也不自动下载大型权重、使用收费 API 或上传私人资料。

部署与缓存两组首版实验已经完成，见 13～14。后续可扩大上下文长度、加入预分配 KV Cache 或做 profiler，但不因为还有可优化项，就一直停在 RAG 指标与微基准上。

本地服务后续增强可按需穿插：流式输出、真正取消、模型 token 预算、阶段耗时、证据级审核。公开部署认证、热切换版本和持久化队列尚未实现，不把本机服务称为生产服务。

最初阶段的停止点是“持久化向量 + 可解释混合检索 + 可用问答 + 可复查记录”，如今已继续到可恢复的小模型训练和 QLoRA 实践。下面保留当时规划，并标注当前状态。

## 原路线：证据层质量（首版已在 06～09 落地）

1. Token 感知切分：解决本轮发现的 70 个超限片段；区分字符、E5 token、生成模型 token；保留稳定来源定位。
2. Reranker：先比较同一候选集合上哪些片段真的包含答案，而不只比主题相似；测增加的延迟和显存，不先假设一定更好。
3. 上下文结构：列表、代码块和“术语→解释”尽量完整保留；一次只改一个因素，区分切分、检索和打包的收益。
4. 证据级审核：另建一小份版本化人工样本，标注具体支持句；不混淆来源文件命中、标签合法和陈述有据三个层级。

阶段完成标志：你能拿出一个“旧上下文缺证据 → 新上下文包含证据 → 回答改善”的具体案例，并解释至少一个未改善案例。

## 原路线：本地服务与数据管理（首版已在 10～13 落地）

- 将硬编码 Vault 路径、模型、检索参数写成明确的项目配置；校验缺失文件和错误参数。
- 增量导入：识别新增、修改、删除笔记；只重新编码受影响的稳定 chunk；记录索引版本。
- 封装 HTTP 服务：进程启动时加载模型，区分存活与就绪检查，控制并发、超时、取消和错误响应。
- 在当前 8GB GPU 上观察 E5/Ollama 共存、冷启动、上下文增长与显存使用；先学会测量，再决定 CPU/GPU 分工。
- 只有在并发与数据规模确实需要时，再引入向量数据库、队列或容器。当前 NPZ 全量矩阵足够用来理解原理，但不是生产存储。

阶段完成标志：服务可启动、可调用、可停止；错误不会静默吞掉；更新笔记后能说明哪个索引版本正在回答。

## 原路线：模型内部与训练实践（基础见 14～17，SFT 数据见 18，QLoRA 进行中）

- 手写小规模张量实验：矩阵乘法、注意力、掩码、位置编码、KV Cache；观察形状、数值和显存。
- 构建一份小而干净的数据集，理解训练/验证切分、数据泄漏和基础损失曲线。
- 再做 LoRA/QLoRA 微调，先定义微调要解决的行为问题，不用微调代替检索补知识。
- 部署训练后的模型并与原模型对比：格式遵循、事实依据、耗时、显存，而不是只展示“能生成”。
