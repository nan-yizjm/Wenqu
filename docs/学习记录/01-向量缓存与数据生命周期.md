# 阶段 1：向量缓存与数据生命周期

## 做了什么

核心代码：`src/vector_retrieve.py` 的 `VectorIndex`、`chunks_fingerprint`、`_load_cached_embeddings`、`_build_embeddings`、`search`。

以前每次查一个问题，757 个 chunk 都重新向量化。现在文档向量保存为 `data/generated/vector_index.npz`；语料和编码配置相同就读缓存，只编码新问题。它是 NumPy 矩阵的精确扫描，不是 FAISS/HNSW，也不是一个向量数据库。

本机实测矩阵为 `757 × 384`，dtype 为 float32。文档和问题分别加 `passage: `、`query: `，向量归一化后用点积算余弦。E5 的维度、前缀约定和 512-token 上限来自[官方模型卡](https://huggingface.co/intfloat/multilingual-e5-small)。

模型权重缓存和文档向量缓存是两件事：前者保存编码器参数，后者保存“这批笔记用这个编码器算出来的结果”。即便后者命中，新 Python 进程仍需加载前者来编码问题。

## 缓存为什么需要版本信息

缓存元数据包含：模型名、固定 revision、语料内容及顺序的 SHA-256、文档格式模板、查询前缀、最大长度、维度、归一化设置、dtype、相关包版本。

最容易忽略的是顺序。如果矩阵第 10 行对应笔记 A，而重载后 chunks[10] 变成笔记 B，分数可能正常，引用却错了。因此只检查“数量还是 757”远远不够。

当前固定本机模型快照：`614241f622f53c4eeff9890bdc4f31cfecc418b3`。不同模型名或 revision 不应该混用同一向量空间。

| 状态 | 意义 | 行为 |
|---|---|---|
| missing | 尚无缓存 | 全量编码并保存 |
| hit | 数据与配置一致，矩阵检查通过 | 直接复用 |
| stale | 语料或配置改变 | 全量重建 |
| invalid | 文件损坏、形状错误、非有限数值等 | 全量重建 |
| forced_rebuild | 显式 `--rebuild` | 全量重建 |

加载禁用 pickle；矩阵检查维度、dtype、有限数值和单位长度。保存采用同目录临时文件写完后替换，避免进程中断时留下半个缓存。它不是多进程锁或事务系统；本版建议只运行一个建库进程。

## 实际发现的问题：70 个片段被截断

本轮对包含标题和前缀的完整 passage 做 tokenizer 计数，70/757 个片段超过 512 个模型 token，约 9.2%。之前的切片按字符数，字符少不代表模型 token 少。

目前只是把截断变成可观测信息，没有消除它。超限部分不参与该 chunk 的向量表达；不能因模型运行成功就声称完整编码了所有笔记。后续应实现 token 感知切分，并保留来源、标题和稳定 ID。

## 怎么使用

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.vector_retrieve "PagedAttention 是什么？"
```

第二次应显示 `hit`，没有文档编码的 Batches 进度条，但可能仍有 Loading weights。需要强制重算时加 `--rebuild`；没有 GPU 时加 `--device cpu`。

换一台机器且没有固定模型快照时，加 `--allow-download` 下载公开模型。这不是每次都需要的选项；当前默认本地加载，避免无必要的 Hub 请求。本轮没有上传笔记，也没有配置 HF token。

更新笔记后的顺序：

```powershell
# 读取当前配置的笔记目录，重生成 documents.json 和 chunks.json；会替换旧派生数据。
.\.venv\Scripts\python.exe -X utf8 -m src.ingest
# 指纹变化时自动重建，不必手工删除目录。
.\.venv\Scripts\python.exe -X utf8 -m src.vector_retrieve "新增笔记涉及的问题"
```

本轮为了固定实验语料，没有重新运行 ingest。笔记路径目前仍在 ingest 中硬编码；下一阶段再独立处理可配置导入和增量更新。

## 小练习

问：只改笔记标题不改正文，要重建吗？参考答案：要，标题路径是 passage 的组成部分。

问：保存文档向量后是否不再需要 E5？参考答案：仍需要 E5 编码新问题；连续问答入口可以复用已加载模型。

问：0.89 是否表示“89% 概率答对”？参考答案：不是，它是向量相似度，主要用于同次检索的相对排序，不能直接充当拒答概率。
