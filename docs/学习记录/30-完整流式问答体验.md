# 30：完整流式问答体验

日期：2026-09-15

## 1. 用户任务

阶段 29 已经能找到原文，但还不是日常可用的问答产品。本阶段完成：

```text
建立会话 → 提问 → 检索当前资料 → 流式回答 → 点击引用
                ↓
          停止 / 重试 / 追问 / 刷新恢复
```

Ollama 和 DeepSeek 使用同一套产品事件协议，但不会自动互相切换。选择 DeepSeek 时，近期会话和本轮检索片段会发给远端；密钥仍只从 Windows 凭据管理器读取。

## 2. 数据与接口

SQLite 从 schema 2 升级到 schema 3：

- `conversations` 保存标题与更新时间；
- `messages` 保存用户问题和助手回答，以及 complete、streaming、stopped、failed 状态；
- `message_sources` 保存回答当时的文档、版本、chunk、章节、定位和预览。

助手消息还保存 provider、model、index version 和实际 retrieval query。由此可以区分“模型说了什么”“它使用哪个索引”“证据当时是什么”。刷新或重启后，会话不是从浏览器缓存恢复，而是重新从 SQLite 读取。

新增接口：

```text
GET  /api/v1/conversations
POST /api/v1/conversations
GET  /api/v1/conversations/{id}
POST /api/v1/conversations/{id}/messages/stream
```

流式接口返回一行一个 JSON 的 NDJSON：`retrieval`、`generation`、`token`、`final`、`stopped` 或 `error`。检索事件先把来源显示出来；随后 token 事件只追加文本；最终事件固定状态和引用检查结果。

## 3. 真流式与停止

旧模型客户端使用 `stream: false`，只能等完整回答。现在：

- Ollama 读取 `/api/chat` 的 NDJSON 行；
- DeepSeek 读取 Chat Completions 的 SSE `data:` 行；
- 浏览器使用 `ReadableStream` 和 `TextDecoder` 增量解析；
- 点击停止先调用显式停止接口设置后端取消事件；服务端关闭上游响应连接，断网或关页时再由流断开兜底取消；
- 已收到的文本保留为 `stopped`，允许重试，但不能被误认为完整回答。

中止 DeepSeek 本地连接不等于服务商一定停止计算或计费，因此界面明确显示这个限制。产品错误只返回稳定错误码和可操作中文提示，不把 API 响应体、密钥或堆栈发给浏览器。

## 4. 追问与证据边界

历史对话有两个用途，必须分开：

1. **理解指代**：例如先问“PagedAttention 是什么”，再问“它解决什么问题”；检索问题会补成“上一问题 + 当前追问”。
2. **维持对话表达**：最多读取近期 8 条、总计不超过约 4000 字符。

历史回答不能作为事实证据。每轮都重新检索当前索引，提示词也明确写出“历史不可引用为事实”。只有本轮 `[S1]` 等检索片段可以作为来源。找不到明确对象时直接要求补充，而不是猜测。

## 5. 产品隔离修正

原 `src.llm` 在被 import 时就调用 `load_env_file()`，这意味着产品只要复用模型客户端，就可能读取开发仓库 `.env`。现在通用客户端不再有导入副作用；只有旧 CLI 的 `create_client()` 明确加载项目 `.env`。产品始终由设置数据库和凭据管理器显式传参。

这是“可复用代码”和“配置来源”必须解耦的例子：复用 HTTP 客户端不代表产品也要继承实验脚本的配置生命周期。

## 6. 真实故障与修正

1. **SQLite 迁移直接失败。** 最初把隐式 `rowid` 放进普通索引定义，SQLite 报 `no such column: rowid`。查询可以用 rowid，不代表索引 DDL 可以把它当显式字段；改为索引 `conversation_id, created_at`。
2. **内部改写触发 OOD。** “当前追问”包含“当前”，被实时信息守卫拒绝。能力边界应判断用户原话，而不是系统内部的检索字符串。
3. **完整问题被误当追问。** “PagedAttention 是什么？它解决什么问题？”含“它”，原规则只要出现代词就要求历史。现在只有以代词或省略问法开头的句子才按追问处理。
4. **前端构建目录错误。** 在仓库根运行 `npm run build` 找不到 package.json；该项目的前端命令必须在 `web` 运行或使用 `npm --prefix web`。
5. **`python -m unittest` 没有发现测试。** Windows 当前布局下它报告 0 tests；全量验收必须使用 `python -m unittest discover -s tests`，不能把“命令成功”误记成“测试通过”。
6. **源码可用但旧发布环境缺 multipart。** 直接调用 PyInstaller 绕过了正式脚本的依赖同步，EXE 在注册上传路由时退出。重新安装 `requirements-product.txt`，并把 `multipart/python_multipart` 作为动态导入显式加入 spec；发布检查必须从完整构建入口开始。
7. **PowerShell 把 NDJSON 读成字节。** 发布包测试的 `Invoke-WebRequest` 对 `application/x-ndjson` 返回 `byte[]`，不能直接 `Trim()`；测试先用 UTF-8 解码，再解析最终 JSON 事件。

## 7. 验收结果

自动测试覆盖：

- Ollama NDJSON 和 DeepSeek SSE 分块解析；
- 回答、索引版本和来源快照持久化；
- 追问改写，且历史被标记为非证据；
- 天气等静态库外请求不调用模型；
- 停止后保存 stopped，随后可重试；
- DeepSeek 没有密钥时明确失败，绝不自动切换 Ollama。

真实浏览器使用合成 `product-demo.md` 和本机 `qwen2.5:7b` 完成了流式回答。回答引用 `[S2]`，点击后正确打开 `RAG 基础流程 > 在线查询` 的第 5 行历史快照；刷新后旧会话仍可读取，浏览器控制台 0 error、0 warning。

## 9. 手动练习与参考答案

1. 为什么 token 到达浏览器后不能只保存在 React state？
2. 为什么追问可以读取历史回答，却不能把历史回答作为 `[S1]` 证据？
3. 为什么停止按钮不能承诺 DeepSeek 已停止计费？
4. 为什么 provider 出错时不自动切到另一个模型？

参考答案：

1. 页面刷新、浏览器崩溃或应用重启会丢失内存状态；服务端必须持久化最终或中止状态，才能恢复完整会话。
2. 历史回答是模型生成物，可能已经有错；它只能帮助理解“它”指什么。事实依据必须重新来自当前资料快照，否则错误会在多轮对话中自我强化。
3. 本地只能关闭 HTTP 连接和停止继续接收；远端任务是否已调度、服务商如何计费不受本地完全控制。
4. 自动切换会改变隐私边界、成本和模型行为。用户选择本地或远端是产品决策，失败应该明确呈现并允许重试。
