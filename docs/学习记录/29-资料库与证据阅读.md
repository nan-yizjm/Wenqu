# 29：资料库与证据阅读

日期：2026-09-15

## 1. 用户任务

阶段 28 只能打开空工作台。本阶段要完成第一条有实际价值的产品路径：

```text
添加资料 → 看处理状态 → 搜索 → 打开结果 → 定位原文
```

资料来源有两种：连接本机 Markdown 文件夹（只读扫描），或上传一份 Markdown/PDF（复制到产品数据）。首版只处理文字型 PDF，不实现 OCR、图表理解和复杂表格还原。

## 2. 数据模型

数据库从 schema 1 迁移到 schema 2，增加六组实体：

- `libraries`：连接的目录或“上传文件”集合；
- `documents`：用户看到的文件和当前状态；
- `document_versions`：每次内容变化生成的不可变快照；
- `document_chunks`：带章节、行号或页码的检索片段；
- `index_versions`：每次成功发布的检索视图；
- `import_jobs`：pending、running、completed、completed_with_errors 或 failed。

正在搜索的请求先取得一个不可变 `SearchSnapshot` 引用。导入线程完成全部数据库写入并建立新 BM25 后，才用锁替换当前引用。因此旧请求不会在执行一半时看到新旧片段混合。历史回答以后保存 `document_id + version_id + locator`，即使原文件更新，也能回看当时的快照。

## 3. Markdown 与 PDF

### Markdown

- 只接受 UTF-8/UTF-8 BOM；其他编码给出可操作错误；
- 识别 1～6 级标题，同时避开代码围栏内部的 `#`；
- 每段限制 800 字符，并保留原始一基 `start_line/end_line`。上限由 E5 的 512 token 窗口倒推：本机笔记语料上实测超窗比例，1600 字 18.4%、1200 字 12.5%、1000 字 7.3%、800 字 0.9%，所以取 800——语义通道不会静默丢掉片段的后半段。已经导入的片段要等文件变化后重新导入才会按新尺寸切分；
- 连接目录忽略隐藏目录，支持 `.md` 和 `.markdown` 的大小写扩展名；
- 导入前后比较 `mtime + size`，文件在读取中变化则本轮失败，等待刷新。

### PDF

- 上传上限 50 MB、页数上限 2000；
- `pypdf` 按页提取文字，每个 chunk 保存 `page`；
- 加密 PDF、坏文件和完全无文字的 PDF 明确失败；
- 某些页面无文字但其他页可用时，文档仍可搜索，并记录警告；
- 原始 PDF 快照通过登记 ID 读取，API 不接受任意本机路径。

浏览器中的 PDF.js 只有在打开 PDF 来源时才动态加载。第一次直接静态导入让首页 JS 从约 239 KB 增到 668 KB；拆分后首页恢复约 239 KB，PDF 阅读代码成为独立约 431 KB chunk，worker 也单独发布。

## 4. 后台任务与失败恢复

文件上传和目录扫描都登记任务。产品运行时把写任务串行执行，避免两个任务同时发布索引造成“较旧任务最后完成反而覆盖新任务”。列表显示处理中、可搜索、失败和已移除。

- 目录刷新：重新扫描；未变化文件不生成新文档版本，也不发布无意义索引版本；
- 文件更新：保存新快照，旧快照保留；
- 文件消失：只从后续检索移除，不删除原目录；
- 上传失败：保留临时原件，允许点击重试；
- 移除上传：从检索中移除，历史版本仍保留供未来会话引用。

同一路径的资料文件夹重复连接时，系统执行刷新并返回原 library ID，避免重复索引同一批文件。

## 5. 新增产品接口

```text
GET  /api/v1/libraries
POST /api/v1/libraries/folders
POST /api/v1/libraries/{id}/refresh
GET  /api/v1/system/folders?path=...
GET  /api/v1/documents
POST /api/v1/documents/upload
POST /api/v1/documents/{id}/retry
DELETE /api/v1/documents/{id}
GET  /api/v1/import-jobs
GET  /api/v1/search?q=...
GET  /api/v1/documents/{doc}/versions/{ver}/source
GET  /api/v1/documents/{doc}/versions/{ver}/file
```

选择文件夹不用系统对话框，而是应用内自带目录浏览（`GET /api/v1/system/folders?path=...` 只读列子目录）。原因是安装版无控制台、无主窗口，它拉起的系统对话框会被创建在浏览器窗口之后，用户看不到（z 序实测与修正过程见[改进记录第 23 节](../../改进记录.md)）。路径只在“用户主动登记目录”时接收；来源接口只能用数据库中的文档和版本 ID，不能传 `C:\...` 读取任意文件。

Markdown 原文按文本行渲染，不执行其中的 HTML 或脚本。命中行使用背景色标记。PDF 使用产品保存的原始快照和页码定位。

## 6. 真实故障与修正

1. **Multipart 不能沿用 JSON Header。** 原 API helper 只要有 body 就强制 `Content-Type: application/json`，会破坏浏览器为 FormData 生成的 boundary。现在识别 FormData，让浏览器设置 multipart header。
2. **PDF.js 增大首页包。** 改为动态 import，Markdown 用户不会在首页解析 PDF 阅读器。
3. **资料已经导入，侧栏仍写“等待添加资料”。** 真实浏览器流程发现状态文字是硬编码；改为读取 setup 中的文档和 chunk 数。
4. **扫描件不是空文档错误。** 对用户明确说明“可能是扫描件，首版无 OCR”，并保留重试入口。
5. **长任务不能直接改当前索引。** 先准备完整快照再交换引用；否则搜索可能看到文档表已更新而 BM25 仍是旧对象。

## 7. 验收

自动产品检查覆盖：

- 中文路径目录接入；
- Markdown 标题、搜索、精确行号；
- 文件更新后 version ID 改变，旧版本仍可读取；
- 上传、移除后不再检索；
- 文字 PDF 命中第 1 页并返回原始 `%PDF` 文件；
- 空白/扫描 PDF 失败且提示 OCR；
- 失败上传可以重试；
- 未登记的文档 ID 返回 404。

Playwright 真实浏览器流程使用合成资料完成：首次向导 → 上传 `product-demo.md` → 搜索“为什么保存来源” → 打开来源 → 显示第 9 行高亮。浏览器控制台 0 error、0 warning，没有使用私人 Vault。

## 9. 手动练习与参考答案

1. 为什么历史引用要保存 `version_id`，只保存 `document_id` 不够？
2. 为什么导入线程需要先建立完整的新索引再交换？
3. 上传文件和连接目录的所有权有什么不同？
4. 为什么 PDF 能提取出字符仍不代表表格结构正确？

参考答案：

1. `document_id` 指向会变化的当前版本；原文更新后，同一行或同一页可能已经是另一段内容。版本 ID 把引用固定到回答时证据。
2. 就地修改会让并发搜索观察到半成品；不可变快照加一次指针交换，使每个请求只看到一个完整版本。
3. 连接目录的原件属于用户，产品只读并保存版本快照；上传文件被复制进产品数据，但“移除”仍只改变登记和检索，历史快照按保留策略处理。
4. PDF 保存的是绘制指令和位置，不一定有逻辑行列；文字提取顺序也可能不同于视觉阅读顺序，所以首版只承诺可提取文本和页码，不承诺表格重建。
