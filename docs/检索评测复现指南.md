# 检索评测复现指南

这份指南回答一个具体问题：**没参与开发的人，怎么在自己机器上跑出同一套口径的检索数字。**

先把一句实话放在最前面：**复现的是方法与口径，不是同一批数字。** `docs/产品检索评测-2026-09-16.md` 里的数字跑在作者的私人笔记上（评测集里的 `expected_source_files` 指向那些笔记），这份语料不可能公开。你能做的是：用同一套代码、同一个判据，**在你自己的语料上跑出你自己的数字**。若要第三方能复现"同一批数字"，需要另做一份脱敏语料 + 配套题集（见 §5）。

评测**只测检索**，不调用任何大模型——全程用不到 Ollama、API key 或联网生成。唯一的外部资产是 E5 编码器的本地快照。

## 1. 准备

```bash
# Python 3.13+（开发环境是 3.14.3）
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-product.txt -r requirements-vector.txt
# torch 不在上面两个文件里钉死；只跑评测的话 CPU wheel 就够（评测里 device='cpu'）：
./.venv/Scripts/python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

模型快照：`intfloat/multilingual-e5-small`，revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`。评测入口**只读本地缓存、不联网下载**（`local_files_only=True`），所以先放一次进 HF 缓存：

```bash
./.venv/Scripts/python.exe -c "from sentence_transformers import SentenceTransformer as S; S('intfloat/multilingual-e5-small', revision='614241f622f53c4eeff9890bdc4f31cfecc418b3')"
```

## 2. 评测集的格式

`data/eval_set.json`（dev 30 题）与 `data/eval_holdout.json`（holdout 12 题）是数组，每题：

```json
{"id": "retrieval-001", "category": "comparison",
 "question": "GRPO 和 RLVR 有什么关系？",
 "expected_source_files": ["05_训练与后训练/训练与后训练.md"],
 "expected_keywords": ["GRPO", "RLVR", "可验证奖励"]}
```

- `expected_source_files` 是相对语料目录的路径 → **严格口径**用（只认这份权威笔记）
- `expected_keywords` → **宽松口径**用（任何一份全文覆盖到这些词的文档都算对）

换你自己的语料，就要写你自己的题集——这一步没有捷径，它决定评测有没有意义。

## 3. 跑

```bash
./.venv/Scripts/python.exe -X utf8 -m src.evaluate_product_retrieval `
  --vault "<你的语料目录>" --data-dir data/generated/product_eval --rubric both
```

- 首次跑会做全量入库（作者 101 篇 31.8 秒）并建向量索引；**复用同一个 `--data-dir` 是增量**，删掉则重建。
- `--rubric both` 是默认值，一次跑出两张表；`--output` 指定报告落点（JSON 里逐题保存两套判定与每一路命中的 `channels`/`channel_scores`/`matched_tokens`）。
- 加 `--sweep 方式:参数=值` 可做单变量实验，例如 `--sweep hybrid:rrf_k=10 bm25:b=0.3`；**每条条件开始前都会把五个参数写回默认值再打补丁**，条件之间不会互相污染。
- 规模参考：dev 30 + holdout 12、11 条条件、两套口径，一次约 8 分 44 秒。

## 4. 怎么读结果

每个评测集会出两张表（严格 / 宽松），列是 R@1 / R@5 / R@8 / MRR，分母只计入在库内、有期望答案的题（知识库外题目单独记"0/4"，拒答由查询守卫负责，不计入指标）。

- **宽松口径**（`lenient_summary`）：**对使用者而言算不算答对**——最早一份"全文覆盖全部期望关键词"的文档排第几位。对外叙述用这套。
- **严格口径**（`summary`）：**权威笔记有没有被顶到前面**——只认 `expected_source_files`。做默认值与参数取舍时用这套，因为它有区分度（宽松口径在 holdout 上已经饱和，分辨不出参数差别，见评测报告 §18）。
- 宽松判据是按语言分组的：关键词分成中文组与拉丁组，**任一组（≥2 个关键词）全命中即算覆盖**；单关键字的组不能独立成立。这是 2026-09-17 定下的口径，**已知残留局限**：少数语言组只有 1 个关键词的题（dev 7 题、holdout 1 题），该语言仍无法单独成立。

## 5. 如果你想让第三方复现"同一批数字"

目前做不到：语料是私人笔记。可行的路径是做一份**脱敏公开语料 + 配套题集**（产品随包已有合成示例的机制可复用），把它的数字也跑出来并写进报告——那时"可复现"才算真正成立。这件事在 `docs/README.md` 的方向文档里挂了很久，做不做、什么时候做，需要使用者拍板。

## 6. 复现报告里的那张矩阵

```bash
./.venv/Scripts/python.exe -X utf8 -m src.evaluate_product_retrieval `
  --vault "<语料目录>" --data-dir data/generated/product_eval `
  --sweep hybrid:rrf_k=10 hybrid:rrf_k=20 hybrid:rrf_k=100 `
          bm25:b=0.3 bm25:b=0.5 bm25:heading_repeat=0 bm25:heading_repeat=2 `
          bm25:k1=1.2 hybrid:candidate_k=40 `
  --rubric both --output data/generated/sweep_matrix.json
```

参数的默认值、类型与上下限见 `src/product/materials.py` 的 `RETRIEVAL_PARAMETERS`；`b`/`k1` 是短名，落到的设置键是 `bm25_b`/`bm25_k1`。
